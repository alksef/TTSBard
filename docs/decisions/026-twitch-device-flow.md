# DECISION-026 — Авторизация Twitch через Device Code Flow

**Статус:** `accepted` (утверждено пользователем 2026-10-10)
**Связано:** [ROADMAP-132](../roadmap/active/132-twitch-api.md), [DECISION-025](./025-shared-secret-store.md)

## Контекст

Нужно разрешать отправку в собственный канал и приглашать владельца другого
канала по ссылке. Localhost callback приложения не принимает возврат авторизации
с чужого компьютера. Пользователь проверил авторизацию канала по коду и утвердил
переход на этот способ.

## Решение

Основной поток авторизации **каналов** — Device Code Flow через twitch-rs с
разрешением `channel:bot`. «Добавить канал» показывает ссылку с кодом и отдельные
кнопки копирования и открытия. Владелец подтверждает доступ на Twitch; TTSBard
ожидает результат и сохраняет токены локально в зашифрованном хранилище ([DECISION-025](./025-shared-secret-store.md)).
Публичный callback-сайт и ручная передача токенов не нужны.

По запросу пользователя 2026-10-10 авторизация **бота** также переведена на
Device Code Flow с правами `user:write:chat` и `user:bot`. Оба входа показывают
ссылку активации с явными действиями открытия/копирования. Localhost callback
не используется в UI; прежний loopback-код и его специализированные тесты полностью удалены. Проверки конкурентных сессий используют Device Code Flow.
Отдельный локальный сброс удаляет грант бота, сохраняя Client ID/Secret.

## Последствия

- Приложение остаётся открытым до подтверждения, отмены или таймаута ожидания.
- Список хранит несколько разрешённых каналов; отправка идёт только в выбранный.
  Добавление не заменяет уже выбранного получателя.
- Смена получателя при активном подключении автоматически обновляет и перезапускает API-подключение.
- Сброс бота или удаление выбранного канала останавливает активное подключение.
- «Удалить доступ» забывает локальный грант, без отзыва токена на стороне Twitch.
- Успешная проверка исходного потока по коду не заменяет ручную приёмку всех
  сценариев списка, переключения, перезапуска и удаления каналов.
