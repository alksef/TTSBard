# DECISION-020 — Настройка действия VTube Studio требует живого подключения

**Статус:** `accepted`
**Связано:** [ROADMAP-061](../roadmap/completed/061-vtube-studio-action-configuration-and-parameter-replacement.md),
[ROADMAP-060](../roadmap/completed/060-vtube-studio-parameter-input-lifecycle.md),
[DECISION-019](019-integration-settings-arc-contract.md)

> **TL;DR.** Настройка действия набора VTube Studio (способ, имя INPUT, Hotkeys,
> предмет и сохранение) доступна только при живом аутентифицированном соединении.
> IPC `save_vtube_studio_typing_action` отклоняет запрос без такого соединения.
> Это **отменяет** прежний контракт ROADMAP-060 P0.4 («при отключённой VTS
> сохранить только локально, без pending»). Переименование Event-параметра стало
> безопасной заменой: новый INPUT создаётся до persistence, прежний удаляется
> после успешного переключения.

## Контекст

ROADMAP-060 P0.4 разрешал сохранять Event-настройку локально при отсутствии
socket'а — «не заводить pending-флаг, очередь или фоновую задачу». Это ставило
требование создать INPUT позже (на первом тесте/typing). ROADMAP-061 пересмотрел
это как продуктовый дефект: без живого соединения у TTSBard нет гарантии, что
сохранённое имя INPUT вообще существует в VTube Studio, а переименование
оставляло прежний custom INPUT «висеть» в конфигурации VTS и засорять список
параметров.

Два контракта входили в противоречие:

- 060 P0.4: «при отключённой VTS сохранить локально без pending»;
- 061 (контракты 1–3): «без подключения сохранить нельзя — read-only».

Поскольку 061 новее и явно переопределяет поведение сохранения (create-before-
persist, удаление прежнего INPUT), приоритет отдан 061. Пользователь подтвердил
это архитектурное решение при декомпозиции.

## Решение

1. **Единый признак редактируемости** — `VTubeStudioService::is_live_authenticated_connection()`:
   `is_desired_running() && connection_status == Connected && is_authenticated()`.
   Тот же признак используется и backend (guard в начале команды), и frontend
   (`canEditTypingAction = currentStatus === 'Connected' && !busy`).
2. **IPC-команда `save_vtube_studio_typing_action`** отклоняет запрос (`Err`) в
   начале, до любых изменений disk/runtime, если соединение не живое. Никакой
   pending-очереди, флага или фоновой задачи.
3. **Порядок замены Event-параметра** (`Event(old) → Event(new)`, `old != new`):
   `create(new)` → `persist` → (компенсация `delete(new)` при ошибке persist,
   до runtime) → `runtime apply` → `emit` → `delete(old)`.
   - Неуспешное создание нового INPUT → `Err`, persistence/runtime не меняются.
   - Semantic-отказ удаления прежнего INPUT (VTS ErrorID 400/401/402/403) →
     частичный успех: новое действие работает, возвращается предупреждение,
     соединение остаётся `Connected`.
   - Transport-failure удаления → состояние connection/auth/socket обновляется по
     контракту сервиса; новое действие не откатывается.
   - Удаляется только custom INPUT, принадлежащий plugin identity TTSBard
     (ErrorID 402/403 от VTS — foreign/default не трогаются).
   - `Event → Hotkeys/Item` и `Hotkeys/Item → Event` **не** удаляют Event-INPUT:
     пользователь может временно сменить режим без разрушения mapping.
4. **Lifecycle активного keepalive**: при переименовании старый keepalive
   останавливается и старому INPUT best-effort отправляется `0`, чтобы удаление
   не сопровождалось параллельным inject старого имени (error 453). Новое действие
   не запускается автоматически — следующий `typing=true` использует уже
   сохранённое новое имя.

## Почему не «сохранить локально без pending» (060 P0.4)

- Локальное сохранение без живого соединения оставляет в настройках имя, которого
  может не существовать в VTS; первый же inject даст `453`, а пользователь не
  получит обратной связи при сохранении.
- Read-only при отключении честнее: пользователь видит, что изменить нельзя, и
  причина показана явно («Подключитесь к VTube Studio, чтобы настроить действие»).
- Это согласуется с тем, что Hotkeys/Item и так требуют подключённой VTS для
  загрузки списков — единое правило для всего блока действия проще, чем
  режим-зависимое исключение для Event.

## Где зафиксировано

- Настоящий decision.
- ROADMAP-061 (критерии завершения, порядок замены).
- `docs/integrations/vtube-studio.md` — пользовательская инструкция отражает
  «настройка доступна после подключения» и поведение при переименовании.
- Реализация: коммиты `3152a66` (backend), `ce355d9` (frontend).
- При ревью изменений в `commands/vtube_studio.rs` / `vtube_studio/service.rs` —
  проверять порядок `create → persist → runtime → emit → delete` и guard
  `is_live_authenticated_connection` в начале команды.

## Условия пересмотра

Контракт пересматривается, если: (1) появится продуктовое требование
редактировать/сохранять действие в офлайне (например, пред-настройка до первого
запуска VTS) — тогда вводится явное разделение «локально-только-черновик» vs
«требует подключения», но не возврат к тихому сохранению несуществующего INPUT;
(2) VTS добавит асинхронное подтверждение создания/удаления, меняющее
транзакционные гарантии; (3) обнаружится, что read-only блокирует реальный
user-flow (например, восстановление после краша VTS).
