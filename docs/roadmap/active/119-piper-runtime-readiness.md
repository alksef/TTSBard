# Готовность Piper до загрузки модели

## Проблема

Piper может загрузить ONNX-модель без доступных данных eSpeak NG. Отсутствие
или повреждение `espeak-ng-data` обнаруживается лишь при синтезе:
`Phonemization failed: Failed to initialize eSpeak-ng (code 0)`.
Пользователь видит выбранную модель, хотя озвучивание не готово.

Сейчас `LocalModelTts::init_espeak_data` только выбирает путь или пишет warning;
`prepare` загружает модель без проверки фонемизации. При восстановлении Piper
на старте ошибка подготовки также только логируется. eSpeak может использовать
системную установку через реестр Windows, поэтому отсутствие папки рядом с exe
само по себе не доказывает неготовность.

## Ожидаемое поведение

- На старте backend проверяет доступность и работоспособность eSpeak до
  автозагрузки выбранной Piper-модели. Результат сохраняется в памяти на время
  работы приложения: готов / не готов с понятной причиной.
- Проверка использует согласованное с библиотекой разрешение пути и реальную
  инициализацию фонемизации. Пустая, повреждённая или неполная папка не даёт
  ложного «готов». Рабочая системная установка остаётся допустимым источником.
- Общая проверка использует нейтральный голос и не зависит от первой выбранной
  модели. Голос из конфигурации каждой модели проверяется отдельно перед ONNX:
  ошибочный голос не блокирует остальные модели и получает отдельное сообщение.
- Если сохранена Piper-модель, но runtime не готов, ONNX-модель не загружается.
  Приложение продолжает запуск и показывает однократную ошибку через общий
  механизм уведомлений приложения. Выбранный Piper не отображается как Ready;
  сохранённый выбор не переписывается молча на другой провайдер.
- Если Piper на старте не выбран, отсутствие данных не создаёт общее уведомление.
  При попытке выбрать Piper-модель загрузка блокируется и показывается ошибка
  уровня приложения. Прежний действующий выбор и настройки сохраняются.
- Общая backend-проверка защищает автозагрузку, ручной выбор и подготовку модели
  для синтеза: обход frontend не приводит к загрузке неготового Piper.
- После восстановления папки пользователь перезапускает приложение для новой
  проверки. Обновление готовности и переинициализация eSpeak без перезапуска
  не входят в эту задачу: зависимость кеширует результат инициализации в OnceLock.

Текст ошибки: «Piper не готов: данные eSpeak NG не найдены или повреждены.
Восстановите папку espeak-ng-data или установку eSpeak NG и перезапустите
приложение». Для известной конкретной причины использовать более точную
локализованную формулировку; техническую диагностику оставлять в логах.

## Scope и точки входа

Одна небольшая задача: readiness eSpeak/Piper и интеграция с существующими
загрузкой, статусом провайдера и общими уведомлениями, без переработки панели TTS.

- `src-tauri/src/tts/piper/runtime.rs` — общий статус готовности и guard перед
  `prepare` / `ensure_loaded` / фонемизацией.
- `src-tauri/src/setup.rs` — проверка до подготовки восстановленной модели.
- `src-tauri/src/state.rs` и команды выбора провайдера — сохранение прежнего
  выбора при отказе, согласованный runtime status.
- Существующая доставка startup notifications и глобальных runtime errors
  в `src/App.vue` — именно ошибка приложения, без дублирования и modal.
- Локали — пользовательская причина и способ восстановления.

Файловую проверку и инициализацию выполнять вне async executor. Не переносить
системные данные eSpeak в пользовательский корень моделей; не менять packaging.
Перед реализацией создать ограниченный task в `.work/ai/` по AI workflow.

## Приёмка

1. Нет доступных данных eSpeak: запуск без выбранного Piper проходит тихо;
   выбор Piper сообщает ошибку и не загружает модель.
2. Сохранённый Piper при тех же условиях: приложение запускается, показывает
   одну общую ошибку, модель не загружена и не имеет статуса Ready.
3. Папка существует, но данные неполные/повреждены: результат также «не готов».
4. Нет папки рядом с exe, но системный eSpeak работоспособен: Piper готов,
   выбор и синтез работают без ложной ошибки.
5. Рабочая portable-папка: выбранная модель загружается, синтез работает.
6. Отказ выбора не меняет активный провайдер и persisted selection;
   повторная попытка не создаёт дубликаты фоновых загрузок.
7. Восстановление данных и перезапуск возвращают готовность. Обе локали и
   существующие пути выбора/озвучивания сохраняют согласованный статус.

Проверки: целевые Rust-тесты через `scripts/cargo.ps1`, проверки IPC/локалей,
frontend build при изменении UI, ручные сценарии запуска и выбора с отсутствующими,
повреждёнными и рабочими данными. Ответ исполнителя не заменяет проверку.
