# ROADMAP-073 — Читаемый маршрут фразы и результат доставки

## Контекст

Маршрут текущей фразы кодируется служебным префиксом в самом тексте:

| Ввод | Фактический маршрут |
|---|---|
| без префикса | TTS + WebView + Twitch |
| `!` | TTS + WebView, без Twitch |
| `!!` | только TTS |
| `!t ` | только Twitch |

Префиксы быстры для опытного пользователя, но интерфейс не расшифровывает
выбранный набор. Пользователь должен помнить таблицу и не видит перед отправкой,
куда уйдёт текущая фраза. Маршрут `!t ` «только Twitch» является новым
продуктовым контрактом: текущий speech pipeline всегда предполагает синтез, а
Twitch получает строковое событие без корреляции с job и без наблюдаемого
результата доставки.

Задача состоит не в добавлении множества переключателей. Маршрут должен быть
одним компактным, читаемым состоянием текущей фразы, а результат — честно
отличать принятие запроса от фактической доставки.

## Цель исследования

Спроектировать request-local routing contract, который:

- немедленно расшифровывает `!`, `!!` и `!t `;
- позволяет выбрать альтернативный маршрут без запоминания синтаксиса;
- поддерживает «только Twitch», когда Twitch действительно подключён;
- сообщает результат доставки конкретной фразы;
- не превращает action bar в матрицу независимых каналов.

## UX-направление

Предпочтительный control — один компактный перебираемый selector текущего
маршрута, а не независимые chips `TTS / Twitch / WebView`:

```text
Маршрут: [Везде · Голос + WebView + Twitch ▾] [☆]    [Озвучить]
```

Начальный набор осмысленных вариантов:

1. `Везде` — TTS + WebView + Twitch;
2. `Без Twitch` — TTS + WebView, legacy `!`;
3. `Только голос` — legacy `!!`;
4. `Только Twitch` — новый shortcut `!t ` и request-local policy без синтеза.

Selector показывает иконки и короткое название. Полная расшифровка доступна в
tooltip/accessible label. Каждый вариант также показывает свой shortcut:
`без префикса`, `!`, `!!` или `!t`. Selector можно раскрыть либо последовательно
перебирать с клавиатуры/мышью. При вводе префикса отображаемый маршрут
обновляется сразу, поэтому префиксы становятся обучаемыми power-user shortcuts,
а не скрытым протоколом.

Рядом находится маленькая кнопка `Сделать маршрутом по умолчанию`. Контурная
иконка означает, что текущий выбор отличается от default; заполненная иконка
внутри selector означает текущий default. Полное назначение доступно в tooltip
и `aria-label`, поэтому смысл не зависит от знания символа звезды/закладки.

Default route сохраняется в settings. После каждой успешно принятой отправки
текущий route возвращается к default. Неуспешная отправка сохраняет текущий
route и текст для исправления или retry. Переключение вкладок не должно
случайно делать временный route новым default.

Для `Только Twitch` primary action должен называться `Отправить в Twitch`, а не
`Озвучить`. Обычный `Enter` выполняет выбранное действие; быстрый редактор может
закрыть окно только после успешного принятия хотя бы одним выбранным consumer.

В полном режиме delivery controls примыкают к primary action справа:

```text
[Меню] [История]  [Голос + WebView (!) ▾][☆]  ☑ Передавать набор     [Озвучить]
```

В compact/minimal mode остаются только route/default/typing/action icons в том
же порядке. Selector показывает набор иконок destinations; текстовое название и
shortcut остаются в tooltip/accessible label и раскрытом списке.

`!t` распознаётся как самостоятельный token только в конце ввода либо перед
whitespace: `!t` и `!t сообщение`. Строка `!thanks` сохраняет legacy-семантику
одинарного `!` и текст `thanks`; это исключает несовместимое поглощение первой
буквы английской фразы. Специализированный `!t` проверяется до общего `!`.

## Default и lifecycle текущего маршрута

1. Persisted default определяет route пустого редактора и начальное состояние
   новой вкладки.
2. Префикс или selector меняет только route текущей фразы.
3. Кнопка default явно сохраняет текущий route как новый persisted default.
4. В selector текущий default отмечен отдельной иконкой; цвет не является
   единственным носителем этого состояния.
5. После принятой отправки route sender-вкладки сбрасывается к актуальному
   default вместе с безопасной очисткой неизменившегося текста.
6. Ошибка до принятия или отсутствие любого доступного destination не очищает
   текст, не сбрасывает route и не применяет quick-editor post-submit policy.
7. Ответ старой отправки не сбрасывает route другой вкладки или новый route,
   выбранный пользователем во время `await`.
8. Current route хранится вместе с вкладкой, чтобы переключение и восстановление
   черновика не меняло смысл уже подготовленной фразы.
9. Распознанный prefix имеет приоритет над сохранённым current route и сразу
   синхронизирует selector. Явный выбор в selector удаляет/заменяет распознанный
   leading prefix и записывает typed current route, поэтому одновременно двух
   конфликтующих источников истины не остаётся.
10. После удаления prefix вручную selector возвращается к current route вкладки,
    а не молча сохраняет прежнее prefix-значение.

## Быстрое отключение typing

Рядом с route control нужен отдельный компактный checkbox/toggle
`Передавать набор`. Он управляет transient typing-state редактора, а не
маршрутом готовой фразы:

- включено — `useTypingBurst` независимо отправляет transitions в WebView и
  VTube Studio по существующему контракту;
- выключено — новые пользовательские правки не публикуют typing transitions;
- выключение во время активного burst сначала выполняет `typing=false` для всех
  consumers и только затем подавляет новые `typing=true`;
- ошибка или отсутствие одного consumer не задерживает второй;
- настройка сохраняется как editor-level default и видна в полном и compact
  режимах;
- toggle не включает и не подключает WebView/VTube Studio сам по себе.

Один общий toggle предпочтительнее двух integration-specific checkbox: typing
является одним доменным сигналом редактора, а consumers уже независимо решают,
могут ли его принять.

## Разделение состояний

Нужно различать три уровня:

1. **Route intent** — куда пользователь направляет текущую фразу.
2. **Integration readiness** — способен ли канал сейчас принять запрос.
3. **Delivery outcome** — что произошло с конкретной отправленной фразой.
4. **Typing enabled** — публикует ли редактор transient typing-state независимо
   от доставки готовой фразы.

Глобальный статус интеграции не доказывает доставку конкретной фразы, а
выбранный маршрут не должен окрашивать отключённую интеграцию как работающую.

## Решение: семантика успеха Twitch delivery

Twitch IRC не подтверждает `PRIVMSG` серверным ack (echo-message capability в
этой работе не используется). Максимально наблюдаемая истина:

- **delivered** — синхронный `write_all` PRIVMSG в установленное TLS-соединение
  при runtime-статусе `Connected` завершился без ошибки;
- **failed** — клиент не `Connected` (включая отключение во время отправки),
  writer недоступен или write вернул IO-ошибку.

Существующий fire-and-forget канал `TwitchEvent::SendMessage` (используется
speech pipeline) не даёт результата и не считается доставкой: tracked-путь для
Twitch-only идёт напрямую к клиенту через разделяемые Arc-поля, минуя этот
канал. UI не показывает `Twitch ✓` для сообщений, ушедших через
fire-and-forget путь.

## Предварительные архитектурные ограничения

1. Backend остаётся источником истины для разбора legacy-префиксов и итоговой
   delivery policy.
2. Новый контракт использует типизированную policy; `!t` остаётся обучаемым
   shortcut, а не единственным представлением Twitch-only route.
3. Route и delivery outcome коррелируются устойчивым request/job id.
4. Twitch-only выполняется отдельной typed text-delivery command, не создаёт
   фиктивную TTS-задачу и не запускает synth/decode/DSP.
5. UI не показывает `Twitch ✓`, если известен только факт постановки события во
   внутренний channel.
6. Недоступный consumer получает outcome `skipped_unavailable` и не отменяет
   работу остальных destinations.
7. Если недоступны все destinations выбранного route, запрос не считается
   принятым: текст и current route сохраняются, quick-editor policy не
   применяется.
8. Расширение routing не возвращает общий mutable prefix state и сохраняет
   request-local snapshot semantics speech pipeline.

## Возможные этапы после исследования

### P0 — Только читаемость legacy-маршрута

1. Распознавать ведущие `!`/`!!`/`!t ` для presentation без изменения остальных
   backend semantics.
2. Показывать рядом с action компактную расшифровку выбранного набора.
3. Проверить изменение/удаление префикса, autocomplete и работу нескольких
   вкладок.

### P1 — Typed route selector

1. Зафиксировать typed current route в модели вкладки и правила приоритета
   selector/prefix/default.
2. Добавить один selector с четырьмя осмысленными маршрутами.
3. Добавить persisted default, кнопку его изменения и reset current route после
   успешного принятия.
4. Согласовать подпись primary action с выбранным маршрутом.
5. Сохранять keyboard-first управление и не требовать открытия dropdown для
   существующих `!`/`!!` сценариев.

### P2 — Управление typing из редактора

1. Добавить persisted editor-level `typing_enabled` с default `true`.
2. Добавить один toggle для WebView и VTube Studio typing consumers.
3. При выключении активного burst гарантированно опубликовать terminal `false`.
4. Покрыть выключение/включение, idle timer, Enter, Escape, unmount и ошибку
   одного consumer.

### P3 — Twitch-only и коррелированный outcome

1. Добавить delivery path без TTS pipeline.
2. Расширить prefix parser с boundary-safe `!t` до общего `!` и обновить
   документацию/тесты совместимости.
3. Проверять фактический Twitch runtime status до принятия Twitch-only request.
4. Возвращать/публиковать коррелированный success/failure outcome.
5. Сохранять текст и route для retry после ошибки.

### P4 — Результат составного маршрута

1. Определить typed outcomes `delivered`, `skipped`, `failed` для каждого
   выбранного consumer.
2. Показать краткий итог последней операции без постоянной панели и без счётчика
   очереди.
3. Продолжать доступные destinations при partial failure и показывать
   недоступные как `skipped_unavailable`.
4. Проверить отключение интеграции во время отправки и zero-destination case.

## Критерии решения

Исследование можно перевести в `planned`, когда:

- выбран один source-of-truth явного current route поверх зафиксированного
  lifecycle `current → submit → default`;
- определена семантика успеха Twitch delivery;
- Twitch-only не маскируется под speech job;
- правила prefix/selector не допускают скрытого конфликта;
- макет читается в compact mode без переноса action bar на несколько строк;
- delivery feedback не дублирует Playback Control.
- typing toggle гарантирует terminal `false` и визуально не является частью
  route selector.

## Не входит

- входящий Twitch chat;
- чтение сообщений зрителей и ответы конкретному пользователю;
- произвольный конструктор всех комбинаций каналов;
- отдельные typing-toggle для каждого consumer;
- постоянный dashboard очереди и интеграций внутри редактора;
- замена существующего WebView/SSE protocol.
