# ROADMAP-120 — Подключение VTube Studio по локальной сети

## Цель

Подключать TTSBard к desktop-версии VTube Studio на другом компьютере
в локальной сети по явно указанному IP-адресу и порту. Существующее
подключение на одном компьютере должно продолжить работать без перенастройки.

## Исходное состояние

- WebSocket endpoint жёстко задан как `ws://127.0.0.1:<port>`
  в `src-tauri/src/vtube_studio/service.rs`, функция `connect_ws`.
- Панель подключения позволяет сохранить только порт; значение по умолчанию — `8001`.
- Авторизация использует сохранённый токен либо запрос разрешения в VTube Studio.
- Настройки действия при наборе доступны при живом подключении.

## Предлагаемый scope

- Добавить адрес сервера в сохраняемые настройки, backend DTO и frontend.
- Для старых настроек использовать `127.0.0.1`.
- Передавать один и тот же endpoint во все пути подключения, включая
  проверку соединения и новую сессию после получения токена.
- При сохранении изменённого адреса или порта завершать прежнюю сессию;
  дальнейшее подключение выполнять к новому endpoint.
- Сохранить действующие правила persistence, авторизации, runtime-статуса
  и защиты от устаревших асинхронных результатов.
- Добавить краткую инструкцию для LAN: Plugin API, фактический порт,
  брандмауэр и подтверждение доступа на компьютере с VTube Studio.

## UI и принятые решения

Реализовано как предпочтительный исходный вариант: в блоке «Подключение» одна строка
«Адрес [127.0.0.1] Порт [8001] [Сохранить]». Оформление повторяет строку адреса
SOCKS5/MTProxy в `src/components/settings/SettingsNetwork.vue`: моно-шрифт полей,
размеры и состояния по эталону, с сохранением локальных компонент панели VTS.
Подписи «Адрес» и «Порт»; поясняющая приписка под строкой не нужна; ввод без `ws://`
и без порта.

Решения по открытым вопросам этапа обсуждения:

- Адрес показывается всегда, без выбора «Этот компьютер / Другой компьютер».
- Ввод принимает IPv4 и имена компьютеров (включая mDNS-суффикс `.local`);
  схема, путь и порт запрещены. IPv6 сознательно не поддерживается: `:` —
  разделитель порта в `ws://host:port` (`validate_vtube_host` в `config/settings.rs`).
- Поле показывает текущий черновик; сохранённое значение — baseline
  revisions/rollback-контракта ROADMAP-115. При сохранении пробелы по краям
  адреса обрезаются; подтверждённое значение обновляет поле, если пользователь
  не успел внести более новую правку.
- Сохранённый токен при смене сервера не сбрасывается: отклонённый токен на
  новом сервере штатно приводит к запросу нового разрешения
  (`perform_authentication`), ложного `Connected` не возникает.

## Реализация

- `VTubeStudioSettings.host` (`config/settings.rs`) с дефолтом `127.0.0.1` и
  `#[serde(default)]`-совместимостью старых settings.json; DTO-поле `host`,
  fixtures перегенерированы.
- `connect_ws`, `connect_and_auth_fresh`, `connect`, `test_connection`,
  `set_typing` принимают `(host, port)`; автозапуск и все команды читают оба
  значения из настроек.
- `save_vtube_studio_settings` валидирует адрес, обрезает пробелы и при
  изменении host или port завершает прежнюю сессию (`disconnect` + emit
  статусов).
- Frontend: поле «Адрес» в панели VTS, `hostError`/`isValidHost` в
  `useVTubeStudio`, host в FIFO-очереди persistence и в rollback-контракте;
  ключи `vtube.host`/`vtube.host_error` в en/ru каталогах.
- Инструкция для LAN — в `docs/integrations/vtube-studio.md` (Plugin API,
  фактический порт, брандмауэр, подтверждение доступа, TCP-проверка).

## Вне первого этапа

Автоматическое обнаружение VTube Studio, подключение через Интернет,
список профилей нескольких серверов и изменение способов управления моделью.

## Приёмка

- Старые настройки подключаются к локальному VTube Studio как раньше
  (тесты serde-совместимости без `host` + fixtures).
- Настройки адреса и порта сохраняются и восстанавливаются после перезапуска.
- Ручное подключение, проверка и автозапуск используют сохранённый endpoint.
- Некорректный адрес не сохраняется (валидация на frontend и backend);
  ошибка не разрушает действующую конфигурацию (rollback-контракт).
- Смена endpoint не оставляет активным соединение с предыдущим сервером
  (disconnect при изменении host или port).
- Отклонённый токен приводит к штатному запросу доступа, а не ложному `Connected`.
- Ошибка соединения и недоступный LAN-сервер корректно отражаются в UI.
- Сценарий на двух компьютерах проверен отдельно от автоматических тестов;
  до такой проверки фактическая LAN-работоспособность остаётся неподтверждённой.
- Есть проверки обратной совместимости настроек, endpoint и lifecycle;
  выполнены frontend build и подходящие Rust-проверки через `scripts/cargo.ps1`.
