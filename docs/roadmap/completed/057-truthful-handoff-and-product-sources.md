# ROADMAP-057 — Достоверный handoff и продуктовые источники

## Контекст

Repository-wide AI-ready scan от 2026-07-30 показал, что часть canonical
документов описывает уже завершённую работу или отменённую архитектуру. Это не
ломает приложение, но делает выбор следующей задачи недостоверным:

- TASK-118 остаётся `planned`, хотя оба включённых режима spellcheck уже
  используют зарегистрированную команду `spellcheck` и покрыты тестами;
- завершённый ROADMAP-040 одновременно описывает исходное отсутствие Vitest и
  Windows Rust tests и актуальный результат с frontend test suite и Windows CI;
- `PROBLEMS.md` оформляет глобальный перехват текста и потоковую отправку по
  terminating characters как действующие MVP-требования, хотя актуальная
  архитектура использует явный `submit_speech → SpeechQueue`;
- автоматическая проверка структуры документации не обнаруживает этот lifecycle
  drift там, где состояние можно проверить объективно.

ROADMAP-041 уже содержит самодостаточную матрицу review-021 и не входит в этот
scope. Запуск frontend и Rust tests в Windows workflow также уже реализован.

## Цель

Сделать корневую карту, active roadmap/tasks и продуктовые требования
достаточно достоверными, чтобы новый разработчик или агент мог выбрать
следующую работу без восстановления истории по коммитам и локальным review.

## Инварианты

1. `docs/tasks/` содержит только будущую самостоятельно исполнимую работу.
2. Completed roadmap явно разделяет исходное состояние и итог, не выдавая
   исторические цифры и отсутствующие gates за текущие.
3. Текущие продуктовые требования не требуют удалённого production flow.
4. Исторические гипотезы сохраняются только с однозначной маркировкой и ссылкой
   на актуальный source of truth.
5. Machine-readable проверка добавляется только для объективного условия и не
   пытается угадывать смысл произвольного prose.

## Этапы

### P0 — Reconciliation текущих документов

1. Перенести устойчивый результат TASK-118 в owning roadmap или профильную
   документацию, после чего удалить task-файл и запись из `docs/tasks/README.md`.
2. В ROADMAP-040 переименовать исходный test baseline и добавить короткий
   актуальный итог без противоречия между разделами.
3. Обозначить `PROBLEMS.md` как историческую постановку либо переписать её
   функциональные требования по текущим README, architecture и roadmap.
4. Сохранить глобальный key-action intercept как действующую функцию, не
   смешивая его с удалённым глобальным перехватом вводимого текста.

### P1 — Проверяемый lifecycle там, где это возможно

1. Добавить в `check-docs.ps1` узкие проверки объективных lifecycle-инвариантов,
   выявленных этим случаем: активная task существует, её индекс и статус
   согласованы, а завершённая task не остаётся в списке текущих задач.
2. Не вводить полный semantic linter Markdown. Не запрещать исторические строки
   в completed/rejected документах, если контекст явно обозначен.
3. Описать короткую reconciliation-проверку перед закрытием roadmap/task в
   AI-assisted workflow или документационной карте.

## Критерии завершения

- TASK-118 отсутствует среди текущих задач, а его результат доступен в
  долговечном owning source;
- ROADMAP-040 не содержит взаимоисключающих утверждений о текущем test/CI state;
- `PROBLEMS.md` не может быть прочитан как требование вернуть удалённый global
  text-interception flow;
- новый lifecycle check имеет positive и negative fixtures либо эквивалентный
  детерминированный тест;
- `./scripts/check-docs.ps1` проходит;
- task-scoped diff не затрагивает product code.

## Outcome

- Завершённый TASK-118 удалён из `docs/tasks/`; его совместимый spellcheck-итог
  сохранён в ROADMAP-055.
- Исходный test baseline ROADMAP-040 отделён от актуального результата, а
  `PROBLEMS.md` однозначно обозначен как историческая постановка со ссылками на
  текущие README и architecture.
- `scripts/check-docs.ps1` теперь двунаправленно сверяет task-файлы с индексом и
  их statuses. Детерминированный Windows PowerShell test покрывает корректный
  случай, missing/unindexed task, status mismatch, duplicate и traversal.
- AI-assisted workflow требует reconciliation canonical status, индекса и
  owning source перед закрытием roadmap/task.

## Не входит

- возврат global text interception или streaming TTS по пунктуации;
- новый online spellcheck provider;
- переписывание всей пользовательской документации;
- автоматическая семантическая проверка любого prose;
- изменение ROADMAP-041 или повторное исправление review-021.
