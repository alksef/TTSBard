# ROADMAP-127 — Упрощение панели WebView и локального подключения

## Цель и границы

После запуска WebView открывается с этого компьютера и из локальной сети без
токена и отдельного включения LAN. Панель строится по аналогии с панелью
«Входящий сервер»: управление сервером, порт, явно подписанные адреса подключения.
Запрос пользователя от 2026-10-06 касается панели настроек WebView; изменение
HTML-шаблона отображения текста не входит в это направление.

Пользователь указал, что локальный WebView менее критичен, чем входящий сервер,
и токен в локальной сети не нужен. Это соответствует текущему backend.
Здесь «Внешний» трактуется как интеграция входящего текста; интернет-доступ
WebView рассматривается отдельно. Пользователь утвердил реализацию:
постоянный bind `0.0.0.0`, удаление настройки bind из конфига и сохранение
трёх остальных блоков без изменений.

## Что уже реализовано

- `src-tauri/src/webview/mod.rs`: стандартный bind — `0.0.0.0`, порт — `10100`.
  Сервер по умолчанию остановлен; LAN-доступ появляется после запуска.
- `src-tauri/src/webview/server.rs`: `/` и `/sse` разрешают локальные адреса
  через `is_local_network` без токена; внешние адреса проходят token/cookie auth.
- `src-tauri/src/webview/security.rs`: локальными считаются IPv4 loopback,
  private, link-local и IPv6 loopback/ULA. Это классификация адреса TCP-клиента,
  а не проверка принадлежности конкретной домашней сети.
- `src/composables/useWebView.ts`: единственный `displayUrl` подменяется
  LAN-IP для `0.0.0.0`; при ошибке определения IP остаётся loopback URL.
- `src/components/WebViewPanel.vue`: пользователь выбирает bind, хотя обычный
  сценарий уже доступен по LAN. Блок URL не различает этот компьютер и сеть.
  Отдельно существуют шаблоны, тест и внешнее подключение с токеном/UPnP.
- Образец формы: `src/components/InputServerPanel.vue` и
  `src/composables/useInputServer.ts`. У Input Server LAN требует токен;
  копировать это поведение в WebView не нужно.

Следовательно, основная задача — упростить форму и представление подключения,
а не заново реализовать LAN-сервер или снимать локальную аутентификацию.
Фактическая доступность с другого устройства зависит также от Windows Firewall
и связности сети; один bind её не подтверждает.

## Согласованная форма

1. **Сервер**: заголовок, фактический статус, запуск/перезапуск/остановка;
   автозапуск и текущая настройка отправляемого текста; строка
   «Порт — поле — Сохранить». Выбор `0.0.0.0 / 127.0.0.1` убрать из обычной формы.
2. **Подключение**: «На этом ПК» — `http://127.0.0.1:<port>/`;
   «В локальной сети» — `http://<LAN-IP>:<port>/`. Каждая строка имеет копирование.
   Дополнительные подсказки про токен и запуск сервера не показывать.
   Пока сервер остановлен, адреса представлены как ссылки для подключения
   после запуска, а не подтверждение доступности.
3. **Шаблоны**, **Тестовое** и **Внешнее подключение**: сохранить текущие блоки,
   порядок, оформление и поведение. Не сворачивать и не переносить.
   LAN не зависит от токена и UPnP.

Использовать существующие `ui-section`, `ui-row`, `ui-composite`, `ui-input`,
`ui-button` и lifecycle-паттерн обеих серверных панелей. Новый общий framework
компонентов и объединение backend двух серверов не требуются.

## Этапы реализации

### 1. Адреса подключения

Разделить loopback и LAN URL в composable; не выдавать fallback `127.0.0.1`
за LAN-адрес. При отсутствии IP показать недоступность определения адреса
и действие повторения. Защитить обновление IP от устаревшего async-результата.
Ссылки используют сохранённый порт, чтобы черновик не выглядел рабочим endpoint.
На нескольких сетевых адаптерах не заявлять, что выбранный IP единственный.

### 2. Форма панели

Перестроить серверный блок и подключение по образцу Input Server. Убрать bind
из обычной формы, добавить подписи URL. Остальные три блока не менять.
Сохранить существующие блокировки операций, сохранение перед запуском,
статусы ошибки и перезапуска. Добавить RU/EN подписи и доступные имена кнопок.

### 3. Старые настройки и документация

Согласовано: удалить `bind_address` из модели WebView, DTO и сохраняемого
конфига. Сервер всегда слушает `0.0.0.0`; старое поле при чтении игнорируется
и при следующем сохранении исчезает. Порт, автозапуск, токен, UPnP и
отправляемый текст сохраняются. Версионная миграция значения не требуется.

Обновить карту UI и профильную пользовательскую документацию. Описание
`docs/user/input-server.md` сейчас расходится с кодом и завершённым
[ROADMAP-118](../completed/118-input-server-lan-token-access.md): там ещё
указан loopback-only сервер. Исправление этого описания выделить отдельно,
если оно входит в согласованный объём.

## Критерии приёмки

- На новой конфигурации после запуска локальная страница и SSE работают без
  query-токена и cookie, в том числе с другого устройства в LAN.
- На этом компьютере есть стабильный loopback URL, отдельно — LAN URL.
  `0.0.0.0` не показывается как адрес браузера; ошибка поиска IP не маскируется.
- Внешняя аутентификация и включение UPnP сохраняют текущий контракт.
- Смена порта, сохранение, запуск, остановка, перезапуск и ошибка занятого
  порта сохраняют понятные статусы и блокировку повторных действий.
- Старый конфиг с `127.0.0.1` загружается; сервер слушает `0.0.0.0`;
  при сохранении поле bind исчезает, остальные значения сохраняются.
- Проверены тестовая доставка, переподключение SSE и перезагрузка шаблонов.
- Панель проверена в Tauri в обеих темах, RU/EN, на минимальной ширине,
  с длинным URL и увеличенным текстом; без горизонтального overflow.
- Backend-проверки — через `scripts/cargo.ps1`; frontend — релевантные тесты
  и `npm run build`; документация — `scripts/check-docs.ps1`.

- 179 целевых frontend-тестов и 80 Rust-тестов WebView прошли; существующий
