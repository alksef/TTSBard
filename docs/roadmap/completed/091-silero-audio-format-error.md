# ROADMAP-091 — Подсказка о формате аудио Silero

## Outcome

В `SileroTts::synthesize` добавлена проверка кодека OGG перед возвратом байтов
в общий аудиопайплайн. Symphonia распознаёт контейнер и кодек по содержимому;
отсутствие декодера Opus или другого кодека OGG возвращает общую короткую
подсказку о смене формата ответа бота на MP3 командой `/mp3`.

MP3 проходит без дополнительного разбора и копирования. OGG/Vorbis остаётся
поддержанным. Ошибки распознавания контейнера передаются существующему
аудиопайплайну; проверка не является полной валидацией повреждённого аудио.
Обработка эффектов и запись кэша при этой ошибке не запускаются. Существующий
префикс «Ошибка синтеза:» сохраняется, сообщение доходит до toast и Playback
Control через очередь речи.

Независимая проверка: 17 тестов Silero, 159 тестов очереди (1 ignored),
6 frontend-тестов уведомлений, Rust check и проверка документации прошли.
Тестовые OGG/Opus и OGG/Vorbis — синтетический тон 440 Гц длительностью 0,1 с,
созданный FFmpeg; кодеки проверены через ffprobe. Тесты подтверждают новую
ошибку, декодирование MP3/Vorbis и отсутствие ложной подсказки на неполном
заголовке OGG. Живой сценарий Telegram → окно приложения в этой сессии
не прогонялся; маршрут ошибки проверен по коду и тестам.

## Цель

Если Silero прислал неподдерживаемое аудио, показать понятную причину и команду
`/mp3` для смены формата последующих ответов бота на MP3.

## Результат анализа

- Telegram принимает ответы с MIME `audio/ogg` и `audio/mpeg`
  ([bot.rs](../../../src-tauri/src/telegram/bot.rs), `is_matching_audio_response`).
  MIME и расширение не различают Opus и Vorbis внутри OGG.
- До исправления [SileroTts::synthesize](../../../src-tauri/src/tts/silero.rs)
  возвращал скачанные байты без проверки кодека.
- В [decode_audio](../../../src-tauri/src/audio/effects.rs) контейнер сначала
  распознаётся, затем создаётся декодер. Сообщение со скриншота
  `Failed to create decoder: unsupported feature: core (codec):unsupported codec`
  соответствует второму этапу, а не ошибке Telegram или таймауту.
- В [Cargo.lock](../../../src-tauri/Cargo.lock) закреплена Symphonia 0.5.5;
  подключены OGG и Vorbis. Согласно [документации этой версии](https://docs.rs/crate/symphonia/0.5.5),
  декодера Opus нет. Пользователь подтвердил, что от Silero приходит OGG/Opus:
  отсутствие декодера Opus объясняет ошибку в этом сценарии. Формат установлен
  из уточнения пользователя; исходный аудиофайл локально не исследовался.
- [TTS pipeline](../../../src-tauri/src/commands/tts_pipeline.rs) добавляет
  технический префикс ошибки. При включённых эффектах префикс другой, поэтому
  разбор строки toast не подходит для распознавания формата.

## Поведение

Кодек определяется по содержимому аудио на границе Silero до общей обработки
эффектов. Для подтверждённого неподдерживаемого кодека OGG возвращается:

> Формат аудио Silero не поддерживается. Смените формат ответа бота на MP3 командой /mp3.

Текст одинаков для Opus и другого подтверждённого неподдерживаемого кодека OGG.
Повреждённые или пустые файлы не выдавать за ошибку выбора формата.
Использовать существующие уведомления очереди и Playback Control
([ROADMAP-084](../completed/084-speech-queue-global-error-toast.md)).

## Границы и приёмка

- MP3 и поддерживаемый OGG/Vorbis продолжают работать; запрета всех OGG нет.
- Ошибка зависит от фактического кодека, а не MIME, расширения или поиска
  английского текста ошибки; проверить файл с неверным расширением.
- Проверить реальные образцы MP3, OGG/Opus, OGG/Vorbis, пустой и повреждённый файл.
- Подсказка работает с включёнными и выключенными эффектами; следующая фраза
  в очереди обрабатывается, после `/mp3` повторная попытка успешна.
- Другие TTS-провайдеры и SoundPanel не получают совет переключить Silero.
- Сохранить корреляцию Telegram-ответов. Автоматическая отправка `/mp3`,
  конвертация аудио и обновление декодера не входят в этот пункт.

## Документация

Подсказки опубликованы в начале README и roadmap, команда добавлена в настройку
Silero в руководстве как действие при ошибке неподдерживаемого формата.
Короткий [FAQ](../../faq.md) объединяет формат ответа, ошибку декодирования
и работу поверх игр. В FAQ описана отправка `/mp3` через редактор без фильтрации
команд и возможная ошибка ожидания аудио после успешной смены формата у бота.
2026-09-04 формулировки согласованы с пользователем; фильтрация команд и
поведение генерации не изменены.
