# ROADMAP-108 — Локальная веб-форма входящего текста

## Контекст

Входящий сервер уже принимает готовый текст на loopback endpoint
`POST /v1/speech` и передаёт его в общий intake: в зависимости от настроек
реплика сразу попадает в `SpeechQueue` либо ожидает ручного разбора во
«Входящих». Для ручной отправки из браузера пользователю пока приходится
создавать собственный клиент или использовать тестовое поле в основном окне
TTSBard.

Нужна минимальная браузерная поверхность того же сервера: одно поле ввода,
отправка текста и понятный результат. Основной игровой сценарий — открыть её во
встроенном браузере Steam Overlay поверх игры и отправлять произвольные реплики
без Alt+Tab или собственного внедряемого оверлея TTSBard. Страница при этом не
является Steam-интеграцией и должна работать в любом обычном браузере на том же
компьютере.

## Цель

Добавить на существующий Input Server локальную веб-форму, которая отправляет
текст через его текущий HTTP-контракт и не создаёт отдельный listener, порт,
очередь или путь озвучивания.

Пользовательский поток:

```text
Steam Overlay / обычный браузер
      GET /overlay
      POST /v1/speech { text }
                │
                ▼
Input Server 127.0.0.1:<настроенный порт>
                │
                ▼
общий intake → Входящие или SpeechQueue → TTS
```

## Архитектурная граница

- Страница обслуживается существующим Axum router входящего сервера на том же
  loopback listener и пользовательском порту; default остаётся `10101`.
- Канонический адрес формы — `GET /overlay`; существующие `GET /health` и
  `POST /v1/speech` сохраняют контракт.
- Форма отправляет same-origin запрос на относительный `/v1/speech`, поэтому
  CORS не добавляется и текущий `Host` gate продолжает защищать все маршруты.
- HTML/CSS/JavaScript поставляются вместе с приложением и не требуют CDN,
  внешних ресурсов, Steam SDK или доступа к сети.
- WebView/SSE server не меняется: он остаётся каналом внешнего отображения, а
  принимающая команду форма принадлежит loopback-only Input Server.
- Страница не получает отдельный доступ к Tauri IPC и не дублирует правила
  intake, snapshot, маршрутизации или очереди.

## Пользовательский контракт MVP

- В форме одно многострочное поле и компактная область статуса, без заголовков
  и кнопок; отправка по `Enter`.
- `Enter` отправляет непустую реплику; `Shift+Enter` вставляет перенос строки.
- Пока запрос выполняется, повторная отправка блокируется.
- После успешного ответа поле очищается и снова получает фокус.
- Ответы `queued` и `pending_review` различаются понятным сообщением: форма не
  обещает немедленное воспроизведение при выключенном автовоспроизведении.
- При ошибке введённый текст сохраняется, показывается безопасное сообщение и
  пользователь может повторить отправку.
- Пустая или состоящая только из пробелов строка не отправляется.
- Страница пригодна для узкого окна Steam Overlay, обеих тем браузера и
  масштабирования без горизонтального overflow.
- Настройки входящего сервера показывают и позволяют скопировать адрес формы с
  фактическим настроенным портом рядом с существующим API endpoint.

## Ограничения и нецели

- Открытие Steam Overlay и выбор его браузерной вкладки остаются действиями
  пользователя; TTSBard не управляет Steam и не вызывает Steamworks API.
- Интерактивная форма забирает клавиатурный фокус. Она убирает Alt+Tab и
  сворачивание exclusive-fullscreen игры, но не позволяет одновременно печатать
  и управлять персонажем.
- Steam Overlay сам внедряется в процесс игры как доверенный компонент Steam;
  TTSBard не внедряет DLL, не hook-ает графический API, не читает память игры и
  не позиционирует функцию как обход античита.
- Отдельный HTTP-сервер, новый порт, LAN bind, UPnP, токен, CORS и объединение с
  WebView server не входят в направление.
- История черновиков, форматирование, выбор provider/voice, управление очередью
  и полноценный редактор не входят в MVP.

## Граничные случаи и риски

- input server остановлен, перезапускается либо сменил порт после сохранения
  адреса в браузере;
- очередь или список ожидающих заполнены (`429`), provider/output не готов
  (`503`), запрос некорректен или текст превышает лимит;
- сетевой сбой с неопределённым результатом: автоматический retry не должен
  незаметно создать дубликат реплики;
- двойной Enter, повторный клик и медленный ответ;
- emoji, кириллица, переносы строк и текст у лимита Unicode-символов;
- старый Chromium Steam Overlay и запрет внешних ресурсов/CSP;
- localhost и `127.0.0.1` должны проходить существующий `Host` gate только с
  фактическим портом listener;
- браузер может не сохранить фокус поля или вкладку между открытиями overlay;
  это проверяется вручную и не маскируется как гарантированное поведение Steam.

## Проверки

- Router tests подтверждают `200` и HTML content type для `GET /overlay`, работу
  существующего loopback `Host` gate и отсутствие CORS-заголовков.
- Тесты страницы или извлечённой клиентской логики покрывают Enter,
  Shift+Enter, блокировку повторной отправки, success/error и сохранение текста
  после ошибки.
- Существующие тесты `/health`, `/v1/speech`, body limit и DNS-rebinding gate
  остаются зелёными через `scripts/cargo.ps1`.
- Frontend build подтверждает корректное формирование и копирование URL формы,
  если для этого меняется Vue UI.
- Ручной smoke в обычном браузере проверяет `queued`, `pending_review`, ошибку,
  повтор и смену пользовательского порта.
- Ручной smoke в Steam Overlay поверх Warframe проверяет доступ к loopback,
  ввод кириллицы, отправку по Enter, возврат фокуса и сохранение вкладки между
  открытиями overlay. Результат фиксируется как наблюдение для проверенной
  версии Steam/Warframe, а не как универсальная гарантия.

## Критерии готовности направления

- При работающем Input Server адрес `http://127.0.0.1:<порт>/overlay` открывает
  автономную компактную форму и отправляет реплику через существующий intake.
- Не создано второго listener, порта, speech submission seam или хранилища.
- Автовоспроизведение и ручной разбор дают те же результаты, что прямой вызов
  `/v1/speech`.
- Ошибка не очищает пользовательский текст и не вызывает автоматическую
  повторную отправку с риском дубля.
- Существующая loopback-only и Host-gate модель безопасности не ослаблена.
- Настройки входящего сервера дают пользователю готовый адрес формы.
- Ручная проверка описывает фактическую пригодность Steam Overlay и известные
  ограничения фокуса без заявлений о совместимости с античитом.

## Outcome

`GET /overlay` на существующем loopback Input Server отдаёт автономную
минималистичную страницу (коммит `e9c5997`): одно поле ввода и область статуса,
без заголовков и кнопок — отправка только по `Enter`, `Shift+Enter` — перенос
строки. Страница не грузит внешних ресурсов, отправляет текст same-origin на
существующий `POST /v1/speech`, различает `queued` и `pending_review`,
сохраняет текст и возвращает фокус при ошибке и не повторяет неоднозначные
запросы. Второй listener, порт, CORS и изменения `Host` gate не добавлялись.
Панель настроек показывает и копирует адрес формы с фактическим портом.

Исходное MVP-требование «кнопка отправки» заменено решением пользователя о
минимализме; router-тесты закрепляют отсутствие `<h1>`/`<button>` в разметке.

Автоматически: 26 router-тестов (включая 4 overlay-теста), 19 тестов
composable, `npm run build`, `cargo check`, `check-docs`, паритет локалей en/ru
и бандл-копии — зелёные; поведение страницы дополнительно прогнано в браузере
на стенде с точной копией разметки. Ручная проверка пользователем пройдена
2026-09-18: форма работает в обычном браузере и в оверлее.

Известные ограничения платформы (см.
[исследование overlay-браузера и записи](../../research/19-steam-overlay-browser-and-capture.md)):
публичного способа закрыть вкладку оверлей-браузера из игры или страницы нет —
штатный цикл `Shift+Tab` скрывает оверлей и сохраняет вкладку; попадание
оверлея в запись зависит от recorder'а (запись Steam и NVIDIA его не пишут,
OBS Game Capture фильтрует ненадёжно на DX12, display capture пишет всё).
