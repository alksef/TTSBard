# ROADMAP-123 — Восстановление после ошибки загрузки настроек

## Цель

Ошибка в файле настроек не приводит к молчаливому сбросу подключений,
учётных данных и пользовательских параметров. Пользователь получает причину
ошибки и может исправить исходный файл либо явно создать стандартные настройки.
В обоих случаях настройки загружаются при следующем самостоятельном запуске.

## Исходное состояние

`SettingsManager::load_from_disk` в `src-tauri/src/config/settings.rs` при
ошибке синтаксиса JSON или десериализации `AppSettings` вызывает
`recover_corrupted_json`: исходник переименовывается в `settings.bak.*.json`,
а вместо него записываются дефолты. Приложение продолжает работу без
пользовательского выбора.

Выявленный случай: лишняя запятая после `storage.audio_cache_dir` вызвала
полный сброс, хотя остальные настройки сохранились в резервной копии.

## Согласованное поведение

1. Оставить текущий строгий JSON-парсер. При ошибке чтения, синтаксиса или
   десериализации остановить обычный запуск и показать модальное окно.
   Подключения, серверы, озвучивание и обычные операции сохранения настроек
   не запускаются. Минимальный запуск интерфейса для диалога допустим;
   продолжения основной инициализации в этом процессе нет.
2. При доступности исходного файла сохранить точную резервную копию с уникальным
   именем рядом с ним. Исходный `settings.json` оставить на месте для правки;
   не перемещать и не заменять дефолтами автоматически.
3. Показать причину, строку и колонку, когда они доступны, путь к исходнику
   и фактический результат создания бекапа. Не показывать значения паролей,
   токенов и ключей в диагностике. Отсутствующий файл при первом запуске
   остаётся обычным сценарием создания стандартных настроек.
4. «Открыть файл настроек» открывает исходный `settings.json` стандартным
   системным вызовом через приложение, назначенное для `.json`. Не выбирать
   редактор принудительно. Модалка остаётся открытой; исправление пользователь
   сохраняет во внешнем приложении. Если вызов не удался, показать ошибку и путь.
5. «Восстановить стандартные» явно заменяет весь конфиг дефолтами только после
   подтверждённого создания резервной копии исходных данных. Запись атомарная.
   Предупреждение о сбросе подключений и пользовательских параметров показывается
   в подтверждении, без отдельной плашки на основном экране. Перед записью
   показать подтверждение с кнопками «Отмена» и
   «Сбросить и закрыть»; начальный фокус на отмене, Escape отменяет сброс.
   При успехе закрыть приложение; при ошибке оставить диалог
   открытым и показать результат без заявления об успешном сбросе.
6. «Закрыть приложение» завершает процесс без замены конфига. Закрытие окна
   и Escape, если поддерживаются, имеют тот же смысл и не означают сброс.
7. После ручной правки или успешного сброса пользователь запускает приложение
   заново. Новый процесс выполняет обычную загрузку; при оставшейся ошибке
   снова показывает диалог. Кнопок повторной загрузки и автоматического
   перезапуска нет.

Если чтение исходника или создание бекапа не удалось, явно сообщить об этом.
Не показывать «Резервная копия сохранена» без подтверждения и не разрешать
замену исходника дефолтами до успешного резервирования.

## Модальное окно

Заголовок: **«Не удалось загрузить настройки»**.

Пример текста при успешном резервировании:

> Ошибка в файле настроек: [причина, строка и колонка, если доступны].
> Резервная копия сохранена: [путь].
>
> Исправьте файл настроек и сохраните его либо восстановите стандартные
> настройки. При восстановлении стандартных настроек подключения и ваши
> параметры будут сброшены. Затем закройте приложение и запустите его снова.

Действия: **«Открыть файл настроек»**, **«Восстановить стандартные»**,
**«Закрыть приложение»**. Сброс не является действием по умолчанию.
Обычный исчезающий toast не заменяет этот диалог.

Формулировки локализуются по действующим правилам приложения. Ошибка в самом
конфиге не должна мешать отображению диалога: нужен встроенный резервный язык
и оформление, не требующие успешной загрузки пользовательских настроек.

Диалог восстановления всегда использует светлое оформление, включая системную
рамку окна, независимо от значения `theme` и возможности разобрать конфиг.
Встроенные RU/EN доступны через переключатель вверху справа. Если сохранённый
язык определить нельзя, используется язык интерфейса Windows: русский → RU,
английский → EN, остальные языки или ошибка определения → EN. Переключение переводит диалог
и заголовок окна без записи в повреждённый конфиг.

## Границы

- Без смены парсера, допуска лишних запятых и автоматического ремонта JSON.
- Без частичного восстановления секций или отдельных полей.
- Без применения исправленного конфига к уже запущенным сервисам.
- Без автоматического выбора или восстановления старых резервных копий.
- Изменение относится к основному `settings.json`; правила других JSON-хранилищ
  не меняются автоматически из-за общего persistence helper.

## Критерии приёмки

- Лишняя запятая, обрыв JSON и несовместимый тип поля вызывают диалог;
  содержимое исходника остаётся неизменным, бекап совпадает с ним побайтно.
- При ошибке обычные сервисы не запускаются и не записывают дефолты поверх файла.
- Файл открывается через системную ассоциацию; ошибка открытия видна в диалоге.
- После ручного исправления и нового запуска сохранённые подключения и остальные
  параметры загружаются. Без исправления новый запуск снова показывает ошибку.
- Явный сброс сохраняет исходные данные, атомарно пишет валидные дефолты и
  завершает процесс. Следующий запуск проходит обычным путём.
- При ошибках чтения, бекапа или записи нет потери исходника и ложного сообщения
  об успехе. Закрытие окна не сбрасывает настройки.
- Первый запуск без `settings.json` и запуск с корректным конфигом работают
  по прежнему обычному сценарию, включая существующие миграции.
- Диагностика не раскрывает секреты; диалог доступен с клавиатуры и читается
  при длинных путях и сообщениях.

## Реализация и проверка

Продуктовая реализация выполняется через task → DeepSeek → независимое review
по [AI-assisted workflow](../../development/ai-workflow.md). Конкретные
разрешённые пути, baseline и путь к временному UI-отчёту задаются в локальном
task в `.work/ai/`. Здесь фиксируется согласованный сценарий, а не готовность
реализации.

## Outcome

Реализован отдельный диалог восстановления вместо молчаливого сброса конфига.
Исходник сохраняется, создаётся точный бекап; файл открывается через системную
ассоциацию. Сброс выполняется после подтверждения и завершает приложение.
Диалог всегда светлый, содержит RU/EN, выбирает сохранённый язык либо язык
интерфейса Windows. Убраны лишние кнопки системной рамки и дублирующее предупреждение.

Исправлено зависание при ошибке записи миграции; регрессионный тест проверяет
сохранность исходника и бекапа. Прошли 181 тест настроек до последних правок,
12 целевых recovery-тестов после добавления системного языка, frontend-сборка,
проверки типов, локализаций и документации. Пользователь подтвердил работу
и завершение направления 2026-10-04. Полная автоматизированная GUI-матрица
не выполнялась; показ диалога подтверждён пользовательскими скриншотами.

Проверить backend-сценарии загрузки и сохранения точечными Rust-тестами через
`scripts/cargo.ps1`; при изменениях UI выполнить релевантные frontend-проверки
и ручную проверку диалога. При добавлении поверхности обновить
[карту UI](../../development/ui-map.md), соблюдая
[правила ручной проверки](../../development/test-cases.md).
