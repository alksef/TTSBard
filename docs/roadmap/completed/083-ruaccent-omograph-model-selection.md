# ROADMAP-083 — Модели RUAccent и UI загрузки

## Цель

Использовать стандартную структуру `ruaccent/accentuator` в едином каталоге и
дать пользователю явное управление выбранным runtime без manifest-файлов и
скрытой загрузки при синтезе.

## Контракт файлов

- Пользователь помещает общие `dictionary` и `nn` непосредственно в:

  ```text
  %APPDATA%\ttsbard\models\ruaccent
  ```

- Discovery сканирует `nn\nn_omograph\<model-id>` и показывает каждый вариант,
  где есть `model.onnx` и `tokenizer.json`, а общий root содержит необходимые
  файлы остальных стадий RUAccent.
- `manifest.json` не используется. Достаточно стандартных файлов с Hugging Face.
- Имя найденного каталога передаётся в `ruaccent-rs`; `tiny` не зашит в TTSBard.
- Одновременно загружается только выбранный вариант.

## Контракт UI

- В строке «Модель RUAccent» размещены компактный selector и icon-only кнопка:
  загрузить, progress, ready или retry.
- Под строкой показан единый live status модели.
- Галка «Загружать при запуске» включает фоновую загрузку после регистрации
  frontend listeners; подсказка предупреждает о возможном увеличении времени
  запуска.
- Галка «Автоматически расставлять ударения» и ручная команда редактора
  доступны только при статусе `Готова`.
- Ошибка переводит модель в `Ошибка загрузки`, показывает глобальное сообщение
  приложения и оставляет кнопку повторной попытки.
- Пункт редактора «Расставить ударения» и его горячая клавиша работают только
  с уже загруженной моделью и не требуют включать автоматическую обработку.
- Empty state не показывает selector и указывает единственный каталог установки.

## Outcome

TTSBard обнаруживает стандартные варианты RUAccent без собственного manifest,
хранит выбранный ID и показывает один источник runtime status в настройках и
редакторе. Загрузка стала предсказуемым действием пользователя либо явной
настройкой старта; синтез и preview больше не создают ONNX session неявно.

## Проверка

- Frontend: 633 tests passed.
- Settings parity и IPC contracts passed.
- Production frontend build passed.
- Runtime loading/retry покрыты Rust и frontend regression-тестами.

## Вне scope

- Одновременное размещение нескольких runtime в памяти.
- Оценка качества каждого варианта модели на отдельном benchmark-наборе.
