# ROADMAP-067 — Контекстное исправление орфографии в редакторе

## Outcome

Контекстное меню исправления орфографии реализовано по правой кнопке мыши и
программной команде. Проверено вручную:

- каждое вхождение подчёркнутого слова имеет собственный диагностический
  диапазон — одинаковые опечатки в разных строках исправляются независимо;
- правая кнопка на подчёркнутом слове открывает меню с вариантами замены, а
  клик вне spellcheck-диагностики сохраняет стандартное поведение WebView;
- выбор suggestion заменяет только конкретное вхождение; редактирование текста
  между открытием и выбором не применяет исправление к устаревшему диапазону;
- меню закрывается по `Escape`, клику снаружи, переключению вкладки и успешной
  замене; открытие меню не меняет выделение и не перемещает курсор;
- волнистое подчёркивание сохраняется, старый hover-tooltip с action-кнопками
  удалён;
- доступна editor-команда `open at cursor/selection` как integration seam для
  `Ctrl+E` (ROADMAP-068); меню clamped по границам viewport;
- выключение орфографии очищает диагностики и меню; включение запускает
  проверку документа;
- состояние недоступности словаря отличимо: под редактором показывается
  сообщение «словарь недоступен» вместо пустого списка диагностик, а следующая
  успешная проверка восстанавливает нормальную работу;
- меню работает в светлой и тёмной темах, при масштабировании и с несколькими
  вкладками.

Продуктовый контракт выполнен полностью. Unit/component-тесты покрывают
диапазоны, повторяющиеся слова, регистр, дефисы, отсутствие suggestions, сбой
IPC, смену настройки и lifecycle меню.

## Контекст

Офлайн-проверка Hunspell уже подчёркивает неизвестные слова и передаёт до пяти
вариантов замены в CodeMirror. Исправление, однако, доступно через стандартный
hover-tooltip lint extension: пользователь должен попасть указателем в точный
диапазон подчёркивания и дождаться появления отдельного popup.

Текущее отображение ненадёжно не только на уровне взаимодействия:

- frontend сопоставляет результат с `tokens.find(...)`, поэтому повторяющаяся
  опечатка привязывается только к первому вхождению;
- lint запускается после idle delay и IPC, но pending/unavailable состояние не
  видно пользователю;
- ошибка IPC превращается в пустой список диагностик;
- незагруженный словарь backend трактует слова как корректные;
- смена настройки орфографии не гарантирует немедленную перепроверку уже
  открытого документа.

## Цель

Сделать правую кнопку мыши основным предсказуемым способом исправления
подчёркнутого слова, сохранив постоянную офлайн-подсветку и подготовив одну
команду открытия меню по позиции для клавиатурного вызова из ROADMAP-068.

## Продуктовый контракт

1. Каждое ошибочное вхождение имеет собственный актуальный диапазон, включая
   одинаковые слова в одной или разных строках.
2. Правая кнопка на подчёркнутом слове открывает компактное меню рядом с точкой
   клика; правый клик вне spellcheck-диагностики не перехватывается.
3. Меню показывает слово, сообщение проверки и до пяти вариантов замены в
   порядке backend. Выбор заменяет только конкретное вхождение.
4. Открытие меню не меняет выделение и не перемещает курсор без необходимости.
5. Меню закрывается по `Escape`, клику снаружи, потере релевантного диапазона,
   переключению вкладки и успешной замене.
6. Изменение текста между открытием меню и выбором не применяет исправление к
   устаревшему диапазону.
7. Старый hover-tooltip с action-кнопками удаляется после появления нового
   пути; волнистое подчёркивание сохраняется.
8. Одна editor-команда открывает то же меню по позиции курсора или выделенного
   слова. Она является integration seam для `Ctrl+E`, но назначение клавиши
   относится к ROADMAP-068.
9. Выключение орфографии очищает диагностики и открытое меню без дополнительного
   редактирования текста; включение запускает проверку текущего документа.
10. Сбой словаря или команды проверки отличим от состояния «ошибок нет» и не
    оставляет визуально устаревшие варианты.

## Этапы

### P0 — Надёжная модель диагностик

1. Сопоставлять результаты с конкретными token occurrences, а не искать первое
   совпадение по тексту.
2. Ввести spellcheck identity/source, по которому контекстное меню отличает
   орфографию от будущих lint-источников.
3. Защитить применение action от stale range после асинхронной проверки и
   последующего редактирования.
4. Обновлять диагностики при изменении enabled/source settings.
5. Зафиксировать тестами повторяющиеся слова, регистр, дефисы, отсутствие
   suggestions, IPC failure и смену настройки.

### P1 — Контекстное меню

1. Определять позицию правого клика средствами EditorView и находить активную
   spellcheck-диагностику в этой позиции.
2. Рендерить одно управляемое меню в координатах редактора с корректным
   viewport clamping на узком окне и возле нижней/правой границы.
3. Перехватывать `contextmenu` только при наличии spellcheck issue.
4. Применять вариант одной CodeMirror transaction к проверенному диапазону.
5. Реализовать клавиатурно вызываемую команду `open at cursor/selection`, не
   назначая ей конкретную клавишу в рамках этого roadmap.
6. Проверить светлую и тёмную темы, масштаб интерфейса, прокрутку и несколько
   вкладок.

### P2 — Достоверная недоступность

1. Не маскировать незагрузившийся словарь под `correct=true` для всех слов.
2. Передать frontend минимальный различимый unavailable/error outcome без
   превращения spellcheck в онлайн-сервис.
3. Не показывать повторяющиеся toast на каждом lint cycle; состояние должно быть
   спокойным и восстанавливаемым после следующей успешной проверки.

## Критерии завершения

- правая кнопка стабильно открывает меню на каждом подчёркнутом вхождении;
- одинаковая опечатка в нескольких местах исправляется независимо;
- правый клик по корректному тексту сохраняет стандартное поведение WebView;
- stale async result или последующее редактирование не исправляет другое слово;
- настройка орфографии обновляет текущий документ без фиктивного ввода;
- hover-tooltip с вариантами больше не конкурирует с новым меню;
- меню доступно мышью и через программную команду у курсора;
- unit/component tests покрывают диапазоны, lifecycle меню и замены;
- проходят `npm test`, `npm run build`, релевантные Rust-проверки через
  `scripts/cargo.ps1` и `./scripts/check-docs.ps1`.

## Не входит

- AI-коррекция, грамматика и отправка текста внешнему сервису;
- пользовательский словарь и действие «Добавить слово»;
- автоматическое открытие popup во время набора;
- назначение и сохранение `Ctrl+E`;
- полная замена Hunspell или словарей.
