# ROADMAP-107 — Текст внешней доставки для WebView и Twitch

## Контекст

Общий speech pipeline преобразует текст перед синтезом: применяет словарные
замены, записывает числа словами, при необходимости выполняет AI-коррекцию и
добавляет provider-specific разметку ударений. Сейчас очищенное представление
этого обработанного текста используется не только для воспроизведения, но и для
доставки в WebView/SSE и Twitch. Поэтому введённое `67 бананов.` отображается во
внешних каналах как `шестьдесят семь бананов.`.

Исходная строка уже живёт в speech job как `original_text`; отдельное постоянное
хранилище текста не требуется. Какой текст получает каждый канал, решает
пользователь: в настройках серверов WebView и Twitch появляются галки сохранения
исходного написания чисел. Галки персистятся рядом со `start_on_boot`,
действуют независимо друг от друга, а выбор читается в момент внешней рассылки
из runtime-настроек сервиса — snapshot и route-флаги не расширяются.

## Цель

Разделить текст озвучивания и текст внешней доставки: TTS получает обработанное
представление, а WebView/SSE и Twitch — текст, выбранный per-server галкой в
настройках сервера. По умолчанию галка применяет пользовательские замены и
подстановки имён, но сохраняет исходное написание чисел и не добавляет
provider-specific разметку ударений. Выключенная галка возвращает полностью
обработанный текст для соответствующего канала.

## Ожидаемый контракт

- Для `67 \fruit` и замены `\fruit → бананов` TTS получает `шестьдесят семь
  бананов`; канал с включённой галкой получает `67 бананов`, с выключенной —
  полностью обработанный текст `шестьдесят семь бананов`.
- У каждого сервера (WebView и Twitch) своя галка; выбор одного канала не
  влияет на текст другого.
- Смена галки действует на ещё не отправленные реплики: выбор читается в момент
  рассылки, а не замораживается в snapshot.
- Из editor-текста перед внешней доставкой удаляется только служебный префикс
  маршрута; сам префикс не должен появляться ни в TTS, ни во внешних каналах.
- Для incoming-текста полная принятая строка остаётся содержимым: она не
  интерпретируется как editor route prefix.
- Словарные замены и подстановки имён применяются к внешнему тексту;
  преобразование чисел, AI-коррекция и автоматически добавленные ударения
  влияют только на TTS. Ручной `+` остаётся частью пользовательского текста.
- `provider_text` остаётся источником для TTS и cache key, а существующий
  очищенный processed text — для очереди, playback labels и истории.
- Twitch-only маршрут, который не создаёт speech job, сохраняет поведение
  прямой доставки введённого текста.

## Предварительный scope

- Получать request-local delivery text из уже сохранённого `original_text` и
  snapshot delivery policy без нового persistence.
- Добавить persisted-поле галки в настройки серверов WebView и Twitch (config +
  runtime-зеркало + DTO + TS-тип); значение по умолчанию — применять замены,
  сохраняя исходное написание чисел.
- Явно провести delivery text через границу подготовки/worker либо вычислить
  его в worker до внешней рассылки.
- Передавать в WebView/SSE и Twitch текст, выбранный per-server галкой (по
  умолчанию delivery text), вместо безусловного processed insert text.
- Не менять TTS preprocessing, cache key, аудиопайплайн и историю; из настроек
  добавить только per-server галку выбора текста.
- Не объединять изменение с transport lifecycle Twitch или политикой длины из
  ROADMAP-104 и ROADMAP-106.

## Граничные случаи

- editor route prefixes и строки, начинающиеся с литерального `!`;
- входящий HTTP/OCR-текст с символами, похожими на route prefix;
- пробелы, переносы строк и IRC sanitation;
- русский текст, emoji и многобайтный Unicode;
- включённые словарные замены, AI-коррекция и ручные маркеры ударения;
- независимые комбинации галок WebView и Twitch для одной реплики; смена галки
  между submit и рассылкой;
- повтор, cache hit, отмена до handoff и параллельные speech jobs;
- независимое отключение WebView или Twitch для конкретной реплики.

## Проверки

- Unit test фиксирует замены и исходные цифры в delivery text, а также число
  прописью в provider/processed text.
- Route-prefix tests подтверждают корректное удаление только editor-префикса.
- Incoming tests подтверждают буквальное сохранение полного принятого текста.
- Routing tests подтверждают per-server выбор payload
  (delivery/полностью обработанный) и отсутствие автоматически добавленных
  provider-specific маркеров.
- Cache hit и обычный synthesis path дают одинаковый внешний payload.
- Существующие тесты очереди, preprocessing, истории и маршрутизации проходят
  через `scripts/cargo.ps1`.

## Критерии готовности направления

- WebView/SSE и Twitch отображают текст реплики согласно своей галке: по
  умолчанию с применёнными заменами, исходными цифрами и пунктуацией, независимо
  от последующих стадий TTS preprocessing.
- TTS продолжает получать нормализованный provider-specific текст.
- Для решения не добавлено новое постоянное хранилище текста; единственная новая
  настройка — per-server галка выбора delivery text или полностью
  преобразованного текста.
- Route policy, отмена, очередь, cache и история не изменили наблюдаемое
  поведение за пределами внешнего текста.

## Outcome

Speech pipeline хранит отдельный request-local `delivery_text` после удаления
служебного route-префикса и применения замен, но до преобразования чисел,
AI-коррекции и автоматической разметки ударений. WebView и Twitch независимо
выбирают его в момент доставки; cache-hit и обычный синтез дают одинаковый
результат. Ручной `+`, явно введённый пользователем, сохраняется. Настройки
персистятся, откатываются при ошибке сохранения, а их чекбоксы имеют стабильный
размер при длинной подписи.
