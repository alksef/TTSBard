# ROADMAP-092 — Одна копия приложения и понятное сворачивание окна

## Цель

Пользователь понимает, что приложение продолжает работать после сворачивания,
и может вернуть его привычным запуском через ярлык. Повторный запуск не создаёт
вторую работающую копию в том же сеансе Windows.

## Исходная проблема

До реализации крестик главного окна скрывал приложение в трей. Пользователь принимал
это за завершение программы и запускал её снова. Без защиты от второго экземпляра
вместо возвращения к текущему состоянию запускалась ещё одна копия.

Точки реализации:

- [App.vue](../../../src/App.vue): собственная кнопка сворачивания; крестик удалён.
- [lib.rs](../../../src-tauri/src/lib.rs): ранняя проверка экземпляра,
  обработка сворачивания и запуск координированного завершения при уничтожении
  главного окна; часть инициализации выполняется до создания Tauri builder.
- [single_instance.rs](../../../src-tauri/src/single_instance.rs): mutex и
  уведомление работающего экземпляра через Windows-сообщение.
- [setup.rs](../../../src-tauri/src/setup.rs): `show_main_window` показывает,
  разворачивает и фокусирует главное окно по клику в трее.
- [commands/mod.rs](../../../src-tauri/src/commands/mod.rs):
  `coordinate_shutdown` координирует завершение приложения.

## Согласованное поведение

Крестик убран из заголовка главного окна в обычном и компактном режимах.
Кнопка «Свернуть» остаётся, с `title` и `aria-label` «Свернуть».

Обычное сворачивание оставляет окно на панели задач. В настройках есть
сохраняемая галка, **выключенная по умолчанию**:

**Скрывать с панели задач при сворачивании**

Пояснение:

> Приложение продолжает работать. Вернуть окно можно через значок в трее или повторным запуском.

При отсутствии нового поля в существующих настройках применяется значение по
умолчанию. Изменение настройки действует со следующего сворачивания и не требует
перезапуска приложения. Поле — `hide_on_minimize`, default `false`.
Миграция прежнего экспериментального `minimize_to_taskbar` не выполнялась:
старое поле не читается как источник новой настройки и не инвертируется.

| Действие | Галка включена | Галка выключена |
|---|---|---|
| Свернуть главное окно | Окно скрыто, доступен только значок в трее | Окно свёрнуто на панели задач, значок в трее остаётся |
| Alt+F4 при активном главном окне | Полностью завершить приложение | Полностью завершить приложение |
| Системная команда закрытия главного окна | Полностью завершить приложение | Полностью завершить приложение |
| «Выход» в трее | Полностью завершить приложение | Полностью завершить приложение |
| Левый клик по значку в трее или «Показать главное окно» | Показать и активировать существующее главное окно | Показать и активировать существующее главное окно |
| Повторный запуск через «Пуск», ярлык или EXE | Показать и активировать существующее главное окно | Показать и активировать существующее главное окно |

Обычные системные способы сворачивания главного окна учитывают ту же настройку,
что и кнопка приложения. Сворачивание не останавливает озвучивание и фоновые
интеграции. Alt+F4 закрывает приложение без дополнительного диалога подтверждения
и проходит через штатное координированное завершение, как «Выход» в трее.

## Единственный экземпляр и повторный запуск

- Ограничение работает автоматически, без отдельной пользовательской галки.
- В одном сеансе Windows работает одна копия TTSBard. Другие сеансы
  независимы; ограничение на учётную запись сразу во всех сеансах не входит
  в согласованный охват. Перенос окна между сеансами не обещается.
- Повторный процесс сообщает работающему экземпляру о запросе показать главное
  окно и завершается. Текущий текст, очередь речи и состояние интеграций первой
  копии сохраняются.
- Скрытое окно показывается, свёрнутое восстанавливается, открытое получает
  фокус. Повторный запуск не переключает видимость обратно в скрытое состояние.
- Проверка единственного экземпляра выполняется до запуска фоновых сервисов
  и изменений общих пользовательских данных вторым процессом.
- Два одновременных запуска и повторный запуск во время начальной загрузки
  не создают две рабочие копии. Второй процесс ожидает готовности приёмника
  и подтверждения запроса в пределах общего таймаута 10 секунд. Принятый до
  готовности главного окна запрос запоминается и выполняется после загрузки.
  Если приёмник не появился или первый процесс не отвечает в этот срок,
  повторный процесс сообщает об ошибке и завершается с ненулевым кодом.
  Неограниченного ожидания и молчаливого успеха без подтверждения нет.
- После аварийного завершения новый запуск не требует ручного удаления файла
  блокировки. Ошибка получения блокировки или связи с первым экземпляром не
  разрешает молча запуск второй рабочей копии.

Реализован собственный небольшой Windows-модуль: именованный mutex в пространстве
сеанса и окно-приёмник для `WM_COPYDATA`. Mutex захватывается в самом начале
`run()`, до настроек, логирования и сервисов, и удерживается до выхода процесса.
Windows освобождает его после аварийного завершения. Ошибка создания приёмника
прерывает старт с явной ошибкой — копия без возможности повторной активации
не остаётся.

Готовый [Tauri Single Instance](https://v2.tauri.app/plugin/single-instance/)
рассмотрен и отклонён: его [Windows-реализация 2.4.4](https://docs.rs/crate/tauri-plugin-single-instance/2.4.4/source/src/platform_impl/windows.rs)
получает блокировку в plugin setup и не защищает инициализацию до Tauri builder,
а в ветке дубликата продолжает работу при неудачном поиске окна. Согласно
[правилам Windows](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces),
mutex без префикса `Global\` ограничен сеансом, что соответствует принятому охвату.

Доставка реализована через `SendMessageTimeoutW(SMTO_ABORTIFHUNG)` с проверкой
подтверждения wndproc вместо неограниченного `SendMessageW`; повторный поиск
окна закрывает промежуток между созданием mutex и приёмника. Ошибки
показываются нативным диалогом (release не имеет консоли) и сопровождаются
ненулевым кодом выхода. Сочетания обычного/повышенного запуска: доставка
`WM_COPYDATA` в повышенный процесс разрешена через UIPI-фильтр; доступ к
mutex определяется штатной DACL объекта — при отказе второй процесс получает
явную ошибку вместо запуска второй копии.

## Критерии приёмки

- [x] В заголовке главного окна нет крестика; кнопка сворачивания доступна в
  обычном и компактном режимах. Обе темы и минимальная ширина не дают переполнения.
- [x] Название и пояснение галки соответствуют тексту выше. Значение сохраняется
  после перезапуска; новая установка и настройки без поля получают `false`.
  Старое поле не влияет на новый default; миграции нет.
- [x] Обе позиции галки проверены для кнопки и системного сворачивания:
  панель задач и трей соответствуют таблице, звук продолжает воспроизводиться.
- [x] Alt+F4 в главном окне, системное закрытие и «Выход» в трее завершают
  весь процесс, сохраняют штатные данные и освобождают ресурсы в обоих режимах
  настройки. Вспомогательные окна не удерживают приложение работающим.
- [x] Запуск через «Пуск», ярлык и EXE возвращает скрытое, свёрнутое или уже
  открытое главное окно с прежним текстом и очередью; второй рабочей копии нет.
- [x] Клик и команда показа в трее восстанавливают окно при обеих позициях галки.
- [x] Быстрый двойной запуск и повторный запуск до готовности первого экземпляра
  оставляют одну рабочую копию и видимое окно после завершения загрузки.
- [x] Задержанное создание приёмника и задержка регистрации callback проверены
  раздельно; принятый запрос выполняется после готовности окна. Зависший приёмник
  не удерживает повторный процесс дольше таймаута доставки; пользователь получает
  понятную ошибку, вторая рабочая копия не запускается.
- [x] После штатного и аварийного завершения повторный запуск успешен без
  ручной очистки блокировки; запуск во время завершения не создаёт конфликт
  владельцев общих ресурсов.
- [x] Проверены сочетания обычного/повышенного запуска; ограничения и фактическое
  поведение активации явно зафиксированы выше. Другие сеансы не блокируются;
  гарантия одной копии на пользователя во всех сеансах не заявляется.

## Outcome

Реализовано в двух итерациях (базовая + доработка по итогам независимого ревью),
продуктовый код — DeepSeek/OpenCode по задачам `.work/ai/2026-09-03-r092-*`,
каждая задача принята отдельным независимым ревью ведущего агента.

- Ранняя блокировка единственного экземпляра первой строкой `run()`; повторный
  процесс выходит за десятки миллисекунд с кодом 0 после доставки запроса,
  никогда не превращаясь в рабочую копию (все исходы доставки — успех, таймаут,
  отсутствие/зависание приёмника, ошибка mutex — покрыты изолированными
  процессными тестами с реальными окнами и message pump).
- Определение минимизации по `window.is_minimized()` (`IsIconic`), а не по
  размеру `Resized`: tauri-runtime-wry пересчитывает размер через `inner_size()`,
  из-за чего прежняя проверка `0×0` не срабатывала — дефект найден пользователем
  и подтверждён первоисточником.
- Настройка `hide_on_minimize` (default `false`, без миграции), 6-местное
  зеркалирование DTO/фикстур/TS, галка с блокировкой повторного сохранения.
- Полный выход по Alt+F4/системному закрытию/«Выходу» через идемпотентный
  `coordinate_shutdown` (скрытые вспомогательные окна больше не удерживают
  процесс).
- Проверки: 1705 Rust-тестов, 844 frontend-теста, clippy (без новых warning),
  parity, IPC-контракты, docs-check, debug-сборка `scripts/build.ps1`;
  runtime-smoke двойного запуска; пользователь подтвердил ручную приёмку
  debug-сборки 2026-09-04.

Пользовательская документация: [guide.md](../../user/guide.md) — раздел
«Сворачивание, трей и выход».

## Границы

Изменён жизненный цикл главного окна и запуск приложения. Самостоятельное
поведение закрытия вспомогательных окон, горячие клавиши их переключения,
автозапуск Windows и общий редизайн настроек не входят в это направление.
Значок и команда «Выход» в трее сохранены.
