# ROADMAP-096 — Английский интерфейс и внешние языковые пакеты

## Цель

Предоставить английский и русский интерфейс из коробки и позволить добавить
перевод на другой язык без пересборки приложения. Пользователь берёт `en.json`
из исходников соответствующей версии, переводит значения, сохраняет под кодом
своего языка, например `de.json`, и помещает в каталог `locales`.
Один пакет покрывает все окна приложения и нативное меню трея.

## Согласованное направление

2026-09-06 пользователь одобрил создание roadmap со следующими требованиями:

- Английский — основной словарь, источник полного набора ключей и резервный язык.
- Английский и русский словари встроены в приложение.
- Внешний JSON позволяет добавить язык для UI и трея без изменения кода.

Сопоставление происходит по постоянному смысловому ключу, например
`common.save` или `tray.quit`, а не поиском русского текста. Переводчик меняет
значения, сохраняя ключи и параметры вроде `{count}`.

## Пользовательское поведение

- В общих настройках есть выбор языка с названиями на самих языках: English,
  Русский и названия обнаруженных внешних пакетов.
- Отсутствие перевода отдельного ключа означает английскую строку на этом месте;
  остальные строки остаются на выбранном языке. Это не переключение всего UI.
- Если выбранный внешний пакет целиком недоступен или невалиден, используется
  английский; сохранённое предпочтение не теряется и восстанавливается при
  возвращении корректного файла.
- Политика первого запуска: английский для новой установки,
  русский для существующих настроек без поля языка. Явный выбор сохраняется.
  Резервный язык всегда English.
- Язык интерфейса не меняет язык TTS, OCR, проверки орфографии, пользовательский
  текст, имена голосов и уже сохранённые названия вкладок/наборов.

### Обнаружение и применение внешнего пакета

Предлагаемые каталоги Windows:

1. `%APPDATA%\ttsbard\locales\` — пользовательские переводы рядом с существующими
   настройками, сохраняемые независимо от обновления приложения.
2. `locales\` в каталоге ресурсов приложения — на Windows рядом с exe;
   путь определяется API Tauri, а не текущей рабочей директорией.

Приоритет для каждого ключа: пользовательский пакет выбранного языка → пакет
рядом с exe → встроенный словарь выбранного языка (если есть) → встроенный English.
Для внешнего `en.json` последним резервом остаётся встроенный English.

«Положить файл и подхватить» означает автоматическое обнаружение и чтение при
запуске приложения. После добавления, изменения или удаления файла пользователь
перезапускает приложение. Новый язык появляется в списке в общих настройках;
пользователь выбирает его один раз. Само появление файла не меняет текущий язык.
Кнопки обновления списка, перечитывания файлов во время работы и наблюдения за
файловой системой нет.

Выбор языка сохраняется для следующего запуска. До перезапуска текущие окна и
трей сохраняют активный язык, а пользователь получает предупреждение на нём.
При следующем старте все окна и трей получают один эффективный словарь.

## Словари и границы архитектуры

- В репозитории предусмотрены `locales/en.json` и `locales/ru.json`; это будущие
  файлы. English содержит все ключи, включая нативные подписи `tray.*`.
- Самодостаточный JSON содержит версию формата, код языка, его собственное
  название и словарь сообщений. Переводчик копирует весь `en.json`, изменяет
  метаданные и значения. Отдельный manifest не требуется.
- Встроенные словари собираются из этих же исходных JSON; копии переводов для
  Rust и Vue вручную не поддерживаются.
- Backend владеет сохранённым выбором языка, обнаружением/валидацией пакетов и
  эффективным словарём. Vue использует общий слой локализации во всех entry points;
  нативные подписи получают значения из того же словаря через backend.
- Предлагаемая UI-библиотека — Vue I18n. До реализации фиксируется единый формат
  интерполяции и множественного числа; нельзя независимо реализовать несовместимые
  шаблоны Rust/Vue. Для простых подписей трея достаточно строк без параметров.
- Известные пользовательские ошибки переводятся по стабильному коду и параметрам.
  Технические подробности сторонних библиотек/сервисов могут оставаться в исходном
  виде; перевод через распознавание текста ошибки не допускается.
- Переводы — данные: не исполнять код и не выводить сообщения как произвольный HTML.
  Валидировать формат, код языка, типы значений, параметры, поддерживаемую версию
  и ограничивать размер входного файла. Неверный пакет не ломает запуск приложения.
- Неполный пакет разрешён; отсутствующие ключи берутся из English. Неизвестные
  ключи старого пакета не используются. Несовместимый формат отклоняется с понятной
  диагностикой. Изменение файла во время работы не затрагивает текущий словарь;
  при следующем запуске невалидный пакет пропускается по правилам fallback.

## Охват

Главное окно, настройки и интеграции, SoundPanel, Playback Control, OCR Selection,
контекстные меню, нативный трей и управляемые приложением заголовки/диалоги.
Переводятся подписи, подсказки, placeholder, aria-label, статусы, пустые состояния,
валидация и пользовательские сообщения об ошибках. Проверить встроенные подписи
редактора CodeMirror и форматирование дат/чисел.

Системные элементы диалогов ОС могут зависеть от языка Windows. Язык установщика,
перевод документации и внешних веб-шаблонов не входят в эту roadmap.

## Этапы

1. Полный английский каталог ключей и слой локализации: проверить на небольшом
   разделе UI и пунктах трея, затем добавить встроенный русский каталог.
2. Сохранение языка, совместимость старых настроек и единое применение к четырём
   окнам и трею при следующем запуске.
3. Последовательный перенос остальных разделов UI и пользовательских ошибок;
   обеспечить английский fallback без зависимости от русского словаря.
4. Внешние пакеты, обнаружение и чтение при запуске, валидация, приоритет каталогов,
   устойчивая обработка неполных/повреждённых файлов.
5. Инструкция переводчику с примером нового языка, проверки покрытия словарей
   и визуальная приёмка; проверить packaged-приложение и запуск без внешних файлов.

Реализация разбивается на ограниченные локальные задачи DeepSeek через
[AI workflow](../../development/ai-workflow.md); roadmap не является prompt агента.

## Критерии готовности

- `en/ru` доступны без файлов рядом с exe; English покрывает каждый используемый
  ключ, Russian имеет полное покрытие поставляемого интерфейса.
- Взятый из исходников `en.json`, переведённый в тестовый третий язык, обнаруживается
  из обоих каталогов после перезапуска. Выбор языка в общих настройках сохраняется
  с предупреждением, а после следующего запуска меняет UI всех окон и трей.
- Удалённый ключ `tray.*` и удалённый UI-ключ независимо возвращают английскую
  подпись. Проверены приоритеты, пустой/повреждённый пакет, несовместимая версия,
  неверные параметры, удаление и восстановление выбранного пакета с перезапуском
  после изменения файлов. Во время работы изменения файлов не применяются.
- Сохранение выбора не теряет другие настройки; проверены новая установка и
  миграция старого settings.json по принятой политике.
- Ошибка сохранения/загрузки не сообщает об успешном применении; текущий словарь
  не меняется до перезапуска.
- Все подписи читаемы при минимальной ширине, увеличенном масштабе и обеих темах;
  нет обрезанных действий и горизонтального overflow из-за перевода.
- Параметры и множественные формы покрыты тестами; контроль ключей отличает
  пользовательские строки от комментариев, логов и пользовательских данных.
- Проверки по изменённым областям: `npm test`, `npm run build`, проверки settings
  и IPC при затрагивании контрактов; целевые Rust-тесты/check только через
  `scripts/cargo.ps1`. Упаковка и внешние ресурсы — через `scripts/build.ps1`.

## Outcome

ROADMAP-096 delivered English and Russian built-in catalogs, restart-only language selection, validated external JSON language packs, and a single effective dictionary for all app windows and the tray. User-facing command failures now show localized operation-specific messages; raw technical text remains available only to diagnostics.
