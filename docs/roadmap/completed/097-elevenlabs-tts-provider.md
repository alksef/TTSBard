# ROADMAP-097 — ElevenLabs как TTS-провайдер

## Контекст

TTSBard уже поддерживает облачные OpenAI и Fish Audio, Telegram/Silero,
локальный HTTP-сервер и динамические Piper-модели через общий registry. Новый
облачный провайдер должен войти в тот же speech pipeline и возвращать готовые
аудиобайты, не управляя очередью, playback или окнами самостоятельно.

В `D:\Projects\TTS-Voice-Wizard` есть рабочий исторический ориентир интеграции
ElevenLabs. Он подтверждает базовый пользовательский сценарий: API-ключ, загрузка
голосов, выбор модели и параметры `stability`, `similarity_boost`, `style` и
`use_speaker_boost`. Этот код не является source of truth для API: он использует
устаревший `GET /v1/voices`, содержит legacy-модели, сопоставляет голос по
неуникальному имени и смешивает UI, сеть и playback.

На момент планирования доступного ElevenLabs API-ключа нет. Контракты и тестовые
ответы строятся по текущей документации API; фактическая проверка аккаунта,
голосов, синтеза и списания credits остаётся отдельным блокирующим gate перед
завершением направления.

По состоянию на 2026-09-08 offline-реализация P1–P4 добавлена и проходит
автоматические проверки. Перед релизом пользователь утвердил documented waiver
для live validation P5: она остаётся ручной проверкой с реальным аккаунтом и не
блокирует закрытие направления.

## Цель

Добавить ElevenLabs в панель TTS как скрытый по умолчанию встроенный облачный
провайдер со стабильным ID `elevenlabs`. Пользователь вводит API-ключ, загружает
доступные аккаунту голоса, выбирает голос и модель, настраивает основные
параметры генерации и отправляет речь через существующую очередь и единый
audio/playback pipeline.

## Пользовательский сценарий

1. Пользователь включает ElevenLabs в меню видимости провайдеров.
2. В карточке он вводит API-ключ и при необходимости включает общий proxy.
3. После сохранения карточка загружает доступные аккаунту голоса. Голос хранится
   и выбирается по `voice_id`; имя используется только для отображения.
4. Пользователь выбирает модель и параметры голоса, сохраняемые атомарно вместе
   с connection settings.
5. После успешной конфигурации ElevenLabs можно сделать активным провайдером.
6. Отправленная фраза проходит обычные preprocessing, history, effects, routing
   и playback без отдельной ветки очереди.
7. Ошибка аутентификации, недоступный голос или модель, нехватка credits,
   rate/concurrency limit, timeout и временная ошибка сервиса показываются как
   понятная ошибка задания и не раскрывают ключ или полный внешний ответ.

## Базовый API-контракт

Первый релиз опирается на следующие endpoints и правила ElevenLabs:

- `POST /v1/text-to-speech/{voice_id}` для завершённого аудиоответа;
- заголовок `xi-api-key` только из Rust backend;
- `GET /v2/voices` для пагинируемого списка голосов;
- `GET /v1/models` для каталога моделей аккаунта (показываются только записи с
  `can_do_text_to_speech=true`);
- при создании ограниченного API-ключа пользователь должен выдать права
  `Text to Speech — Access`, `Models — Access` и `Voices — Read`; без
  `Models` или `Voices` обновление каталога завершается ошибкой
  `missing_permissions`;
- `GET /v1/user/subscription` не входит в MVP и резервируется для отображения
  credits после подтверждения продуктовой необходимости;
- `output_format=mp3_44100_128` как совместимый с текущим decoder вариант без
  требования платного аудиоформата;
- `optimize_streaming_latency` не используется, поскольку параметр устарел;
- HTTP streaming и WebSocket streaming не входят в первый релиз: текущий
  provider-контракт возвращает завершённый `Vec<u8>`.

Модели загружаются из каталога аккаунта (`GET /v1/models`) и показываются
только с `can_do_text_to_speech=true`; встроенный allowlist моделей больше не
используется. Пока каталог не загружен, выбор модели не отображается, а
synthesis/активация провайдера завершаются безопасной ошибкой конфигурации.

Сохранение API-ключа отделено от применения параметров генерации. Если ключ
новый либо локальный каталог отсутствует, после сохранения автоматически и с
видимым loading-состоянием независимо загружаются модели и голоса. Повторное
сохранение того же ключа при наличии обоих каталогов не обращается к API.
Изменение ключа инвалидирует каталоги предыдущего аккаунта и загружает их
заново. Во время первой загрузки ручные кнопки обновления недоступны.

Модель, `output_format`, `stability`, `similarity_boost`, `style` и
`use_speaker_boost` образуют один блок с отдельной кнопкой «Применить».
Изменённый блок явно показывает наличие неприменённых изменений, а кнопка
неактивна при совпадении формы с сохранёнными значениями. Выбранный голос и
`use_proxy` сохраняются и применяются сразу. Модели и голоса имеют независимые
команды и кнопки обновления: ошибка одного каталога не блокирует другой.

## Настройки и данные

Persisted `ElevenLabsSettings` в `settings.json` содержит только настройки:

- `api_key: Option<String>`;
- `voice_id: String`;
- `model_id: String` (пустой, пока каталог моделей не загружен);
- `output_format: String`;
- `stability`, `similarity_boost`, `style` в диапазоне `0.0..=1.0`;
- `use_speaker_boost: bool`;
- `use_proxy: bool`.

Дескрипторы голосов (`voice_id`, `name`, `category`, `labels`, optional
`preview_url`) и моделей (`model_id`, `name`, `can_use_style`,
`can_use_speaker_boost`) хранятся отдельно в атомарно записываемом
`elevenlabs-catalog.json` в config directory. Это восстановимый cache, а не
пользовательские настройки: отсутствующий или повреждённый файл читается как
пустой каталог и может быть заново получен из API. Каталоги из старого
`settings.json` намеренно не мигрируются.

Секрет хранится по существующей политике settings и проходит через DTO только
по уже принятому в приложении контракту. Значение ключа, URL с credentials,
тело внешней ошибки и request body с пользовательским текстом не попадают в
логи. Настройки connection form сохраняются одной owner-level transaction;
runtime обновляется только после успешной записи.

Выбранный voice snapshot входит в `SpeechSnapshot`, поэтому смена голоса после
постановки фразы в очередь не меняет уже созданное задание. История показывает
provider `elevenlabs` и фактический `voice_id` или сохранённое безопасное имя,
не вычисляя голос заново по текущим settings.

## Обработка ошибок и повторов

Backend разбирает безопасную структуру ElevenLabs `detail`, но наружу отдаёт
собственную типизированную/нормализованную ошибку. Минимально различаются:

- неверный или недостаточно разрешённый API-ключ;
- голос не найден либо больше недоступен аккаунту;
- модель недоступна текущему тарифу;
- недостаточно credits;
- превышен request rate;
- превышен concurrency limit;
- превышен лимит длины текста выбранной модели;
- timeout, proxy/connect failure и временная недоступность сервиса;
- успешный HTTP-статус с пустым или недекодируемым audio body.

Автоматический повтор синтеза не выполняется после неоднозначного сетевого сбоя,
поскольку первый запрос мог быть принят и списать credits. Ограниченный backoff
допустим только для заведомо неисполненного запроса и должен быть согласован с
семантикой ошибки ElevenLabs. Обычная последовательная speech queue уже снижает
риск превышения concurrency limit.

## Этапы

### P1 — Контракт, persistence и тестовые данные

- Добавить `ElevenLabsSettings`, DTO и безопасную миграцию старого
  `settings.json` через `serde(default)`.
- Добавить provider kind/ID во все исчерпывающие Rust и TypeScript-контракты.
- Зафиксировать request/response fixtures из документации без реального ключа:
  синтез, страницы голосов и основные ошибки.
- Покрыть defaults, validation, round-trip, redaction и provider identity.

### P2 — Backend provider и registry

- Реализовать отдельный async `ElevenLabsTts` поверх общего `reqwest`/proxy
  helper с timeout и безопасным логированием.
- Сформировать запрос завершённого MP3 с выбранными model и voice settings.
- Реализовать пагинируемую загрузку `/v2/voices` с `has_more` и
  `next_page_token`, bounded числом страниц и защитой от повторяющегося token.
- Добавить initialization, selection, startup restore и runtime update без
  удержания registry/settings lock во время сети.
- Проверить, что reconfiguration не переключает активного провайдера и что
  failed persistence не публикует частично обновлённый runtime.

### P3 — IPC и карточка ElevenLabs

- Добавить атомарную команду сохранения connection/generation settings и
  отдельную команду обновления каталога голосов.
- Создать карточку по визуальному и поведенческому паттерну Fish Audio, но без
  зависимости от его model marketplace.
- Добавить ElevenLabs в меню облачных провайдеров; по умолчанию карточка скрыта,
  активный provider всегда видим.
- Реализовать состояния loading, empty, success, cancel, error и retry для
  голосов; сохранять выбор по ID и корректно показывать одинаковые имена.
- Обеспечить keyboard accessibility, обе темы, узкую ширину и отсутствие
  горизонтального overflow.

### P4 — Независимая проверка без API-доступа

- Проверить serialization и миграцию settings на fixtures.
- Проверить HTTP-клиент через локальный mock server: URL encoding `voice_id`,
  заголовки, query/body, pagination, timeout, malformed JSON, error mapping,
  пустой и недекодируемый audio body.
- Проверить выбор/восстановление provider, immutable snapshot и history metadata.
- Выполнить целевые Rust-тесты и check через `scripts/cargo.ps1`, frontend-тесты,
  `npm run build` и ручную проверку UI без ключа.

### P5 — Live validation после появления доступа

- Проверить restricted API key с минимальными TTS/voices permissions и
  отдельным credit limit.
- Загрузить несколько страниц голосов или подтвердить одностраничный ответ,
  выбрать голос и синтезировать короткие русскую и английскую фразы обеими
  моделями.
- Подтвердить MP3 decode, effects, вывод на обычное устройство и виртуальный
  микрофон, отмену/следующее задание очереди и запись history metadata.
- Проверить реальные ответы для invalid key, недоступного voice/model и
  insufficient credits без намеренного расхода значимого лимита.
- Сверить фактические latency, response headers и API schema с fixtures;
  обновить контракт и пользовательскую документацию при расхождении.

## Критерии готовности

- Старые настройки открываются без ручной миграции, а ElevenLabs по умолчанию
  не выбран и не загромождает панель.
- Ключ никогда не используется frontend для прямого запроса и не появляется в
  логах или пользовательских ошибках.
- Голоса загружаются через актуальный пагинируемый endpoint и выбираются по
  стабильному `voice_id`.
- Синтез использует выбранные snapshot voice/model/settings и возвращает аудио
  в существующий playback pipeline.
- Все заявленные ошибки имеют предсказуемое UI-поведение; ошибка одного задания
  не блокирует дальнейшую очередь.
- Offline/mock проверки P1–P4 проходят независимо от наличия ElevenLabs-ключа.
- Направление не переводится в `completed`, пока не выполнен live gate P5 либо
  пользователь явно не утвердил documented waiver этого ограничения.

## Outcome

ElevenLabs добавлен как встроенный облачный TTS-провайдер со стабильным ID
`elevenlabs`: реализованы persisted settings, отдельный восстановимый каталог
моделей и голосов, атомарное обновление runtime, безопасная обработка ошибок и
диагностика HTTP, карточка настройки и интеграция с общей очередью, history и
playback pipeline.

Offline scope P1–P4 подтверждён автоматическими проверками 2026-09-08:
`scripts/check-docs.ps1`, 1069 frontend-тестов, production frontend build,
67 целевых Rust-тестов ElevenLabs и `scripts/cargo.ps1 check --lib`. Live gate
P5 не выполнен из-за отсутствия доступного ElevenLabs API-ключа и закрыт по
явно утверждённому waiver. Его сценарии из раздела P5 сохраняются как ручной
release smoke-check и не означают незавершённую продуктовую реализацию.

## Вне scope первого релиза

- HTTP/WebSocket streaming и воспроизведение до получения полного ответа;
- voice cloning, voice design, speech-to-speech и speech-to-text;
- pronunciation dictionaries, projects/studio и multi-speaker dialogue;
- preview playback непосредственно из внешнего `preview_url`;
- автоматическая покупка credits или изменение billing settings;
- пользовательский arbitrary ElevenLabs base URL.

## Условия пересмотра

- Если time-to-first-audio завершённого endpoint неприемлем для коротких
  интерактивных реплик, streaming оформляется отдельным архитектурным решением с
  изменением provider/playback контракта.
- Если ElevenLabs изменит доступные модели, voice schema или формат ошибок до
  появления ключа, P5 начинается с повторной сверки официальной документации.
- Если сохранение API-ключей в общем settings-файле будет заменено системным
  credential storage, ElevenLabs мигрирует вместе с другими облачными
  провайдерами, а не вводит отдельный механизм.
