# ROADMAP-052 — Перехват ошибки лимита Silero

## Outcome

Текстовый отказ `@silero_voice_bot`, связанный с текущим запросом озвучки,
теперь сразу превращается в стандартизированную ошибку генерации. Приложение
больше не игнорирует сообщение о превышении лимита и не заменяет его через
30 секунд ложной ошибкой ожидания. Таймаут ответа Silero сокращён до 10 секунд.

Корреляция требует входящее сообщение от peer Silero и ID новее запроса.
Произвольный текст принимается только с точным `reply_to` исходящего сообщения.
Ответ без `reply_to` принимается только при совпадении с известным шаблоном
лимита; явный чужой `reply_to`, посторонний, устаревший или пустой ответ не
завершает ожидание. Обрабатываются полные Telegram updates и
`UpdateShortMessage`; web preview ссылки не мешает распознать текстовый отказ.

Ответ с маркерами `превысит` → `лимит` → `озвучк` либо `лимит` → `озвучк` →
`исчерпан` возвращает «Превышен лимит озвучки Silero.», другой строго связанный
текст — «Silero отклонил запрос.». Исходный текст бота не передаётся в UI и не
сохраняется в штатных correlation-логах.

## Наблюдаемая проблема

В runtime-логе запрос `116634` был отправлен 27 июля 2026 года в 21:12:11.
Silero ответил текстом о превышении лимита озвучки, однако путь синтеза ожидал
только аудио и в 21:12:41 сообщил `Timeout waiting for voice message`.

## Целевое поведение

1. Связанный текстовый ответ Silero немедленно завершает генерацию стабильной
   ошибкой приложения, а не исходным сообщением бота.
2. Аудио продолжает приниматься по строгим правилам ROADMAP-049.
3. При отсутствии связанного аудио или текста ожидание завершается через
   10 секунд.
4. Текст Telegram-сообщения не попадает в обычные `warn`/correlation-логи.

## Проверка

- чистый предикат корреляции покрывает success, link text, outgoing,
  wrong/missing peer, stale ID, exact/wrong/missing `reply_to`, reply-less
  известный лимит, пустой и whitespace-only текст;
- отдельный classifier покрывает обе известные фразы лимита, ссылку между
  маркерами, регистр, неверный порядок, пропущенный маркер и посторонний ответ;
- интеграционный тест покрывает reply-less лимит в `UpdateShortMessage`;
- `cargo fmt --manifest-path Cargo.toml -- --check` из `src-tauri`;
- `cargo check --manifest-path Cargo.toml` из `src-tauri`;
- `cargo test --manifest-path Cargo.toml --no-run telegram::bot::tests` из
  `src-tauri`;
- `./scripts/check-docs.ps1`.

Rust test targets компилируются. Их запуск в текущем Windows checkout по-прежнему
ограничен известной внешней ошибкой native DLL `STATUS_ENTRYPOINT_NOT_FOUND`,
уже зафиксированной в ROADMAP-049; это изменение не добавляет новых native
зависимостей.
