# ROADMAP-122 — Сохранение настроек при запуске интеграций

## Цель

Кнопки запуска и подключения используют параметры, которые пользователь видит
в панели. Отдельное нажатие «Сохранить» перед запуском не требуется.
Сообщение различает сохранение изменённых настроек и результат запуска.

## Исходное состояние

- WebView: «Старт» сохраняет текущую секцию с `enabled = true`, но результат
  показывается как результат сохранения, даже если пользователь просто запускает сервер.
- VTube Studio: подключение использует ранее сохранённые адрес и порт.
- Twitch: подключение и переподключение проверяют поля панели, но используют
  ранее сохранённые реквизиты. Сохранение реквизитов само может инициировать restart.
- Входящий сервер: запуск отделён от сохранения текущих полей панели.

## Поведение

1. Проверить текущие поля. При невалидных значениях показать ошибку без запуска.
2. Сохранить изменённые настройки через существующего владельца persistence;
   дождаться записи и только затем запускать или подключать интеграцию.
3. При ошибке сохранения не запускать интеграцию. Сохранить действующие правила
   rollback и защиту более новых правок пользователя.
4. При ошибке запуска оставить успешно сохранённые настройки и показать ошибку
   запуска; если в этой операции настройки сохранялись, сообщить об этом явно.
5. Обычная кнопка «Сохранить» остаётся. Существующие правила применения настроек
   к работающей интеграции сохраняются; изменение этих правил вне scope.
6. Переподключение/перезапуск, где доступны, также применяют текущие параметры.
   Остановка не должна сохранять посторонние незавершённые правки формы.

Изменения определяются сравнением пользовательских параметров с подтверждёнными
сохранёнными значениями после нормализации. Само переключение запуска, runtime-статус
и уже сохранённые галочки не считаются новыми изменениями настроек.

## Сообщения

| Сценарий | Сервер | Внешняя интеграция |
| --- | --- | --- |
| Параметры изменены, успех подтверждён | «Настройки сохранены. Сервер запущен» | «Настройки сохранены. Подключено» |
| Параметры не изменены, успех подтверждён | «Сервер запущен» | «Подключено» |
| Параметры сохранены, запуск ещё идёт | «Настройки сохранены. Запуск…» | «Настройки сохранены. Подключение…» |
| Параметры не изменены, запуск ещё идёт | «Запуск…» | «Подключение…» |
| Параметры сохранены, запуск завершился ошибкой | «Настройки сохранены. Не удалось запустить сервер: …» | «Настройки сохранены. Не удалось подключиться: …» |

Точные формулировки локализуются на русском и английском. «Запущен» и
«Подключено» появляются только после подтверждённого runtime-результата;
принятие асинхронной команды не считается успехом подключения.
Одна операция не должна выдавать отдельный toast «Сохранено», а затем
противоречащее ему сообщение. Поздние события старой операции не меняют результат новой.

## План реализации

1. WebView: отделить сообщение запуска от сообщения обычного сохранения;
   различать изменённые и неизменённые параметры, учитывать runtime-подтверждение.
2. VTube Studio: валидация и сохранение перед подключением в рамках одной
   операции, без нарушения очереди и защиты от устаревших результатов.
3. Входящий сервер: согласовать существующую очередь сохранения с запуском,
   сохранив backend как источник runtime-статуса.
4. Twitch: сохранить актуальные реквизиты перед подключением/переподключением,
   исключить двойной restart со стороны сохранения и команды подключения.
5. Проверить единые сценарии и обновить пользовательские инструкции.

Каждая интеграция — отдельный локальный task для DeepSeek/OpenCode с ограниченными
путями и независимым review. Общий framework интеграций не вводится.

## Приёмка

- Во всех четырёх панелях изменение параметров → запуск применяет новые значения
  и сохраняет их для следующего открытия приложения.
- Запуск без изменений не сообщает «Настройки сохранены».
- Ошибка сохранения блокирует запуск; ошибка запуска не откатывает успешную запись.
- Проверены невалидные поля, повторные нажатия, сохранение в полёте, правки во время
  ожидания и поздние runtime-события. Новые правки не теряются и не выдаются за сохранённые.
- Twitch не создаёт два подключения из одной операции.
- Отдельные «Сохранить», остановка и автозапуск сохраняют свой контракт.
- Сообщения и статусы проверены вручную в WebView2 на русском и английском,
  включая недоступный сервер и занятый порт; временный отчёт указан в task-файле.
- Выполнены релевантные frontend-тесты, проверка типов и локализаций;
  при изменениях backend — целевые проверки через `scripts/cargo.ps1`.

## Outcome

Реализовано 2026-10-04: WebView, VTube Studio, входящий сервер и Twitch
применяют текущие параметры при запуске/подключении и различают сообщения
с сохранением изменений и без него. Ошибка сохранения блокирует запуск;
ошибка запуска не откатывает успешно сохранённые параметры.

Исправлены обработка промежуточных статусов перезапуска WebView/Twitch,
досохранение реквизитов Twitch во время записи и удержание статуса
«Подключение» с блокировкой кнопок VTube Studio при смене IP.

Автоматические проверки: полный frontend-прогон 1358 тестов после основных
исправлений, затем 131 тест VTube Studio с пятью дополнительными проверками;
frontend-сборка успешна. Пользователь подтвердил работоспособность вручную
2026-10-04, включая исправленный сценарий смены IP VTube Studio.
