# ROADMAP-065 — Саундпанель: раскладка клавиатуры, разделение runtime/config

## Outcome

P1–P3 реализованы. Floating SoundPanel является единственным продуктовым UI
звуковой панели: старая вкладка и пункт сайдбара удалены. В окне работают
QWERTY-сетка A–Z/0–9, режимы runtime/config, управление слоями, 2D-навигация,
назначение файлов и сохранение существующего формата данных.

После основного этапа добавлены:

- прямой выбор слоя `F1–F12` по порядковому номеру; отсутствующий индекс
  игнорируется, а активная SoundPanel имеет приоритет над глобальным Intercept;
- единая кнопка-гвоздик для закрепления, которая управляет blur, Escape и всеми
  путями запуска звука;
- синхронизация светлой/тёмной темы и заголовка с другими окнами;
- собственная прозрачность SoundPanel независимо от источника цвета;
- собственный DOM-dropdown слоёв: WebView2 больше не рисует системный белый
  popup вне палитры панели.

Custom dropdown слоёв вручную проверен в светлой и тёмной темах: меню читаемо,
не использует системный белый WebView2 popup и корректно переключает слой.
ROADMAP-065 завершён.

## Контекст

Сегодня звуковая панель смешивает в одном UI две разные задачи:

- **назначение** звуков клавишам (формы, диалоги, таблица биндингов);
- **воспроизведение** звуков по нажатию.

`SoundPanelTab.vue` (`src/components/`, ~822 строки) — это config-панель внутри
главного окна: таблица биндингов, диалог добавления, переключатель наборов. Уже
сейчас её поведение частично дублирует `SoundPanelApp.vue`
(`src-soundpanel/`, floating окно), который ловит локальный `keydown` и играет
звук через `sp_play_binding` — то есть **runtime-поведение уже вынесено в
отдельный компонент**, но визуально это урезанная копия, а не раскладка
клавиатуры.

Глобальных хоткеев для клавиш A–Z нет (только window-show хоткей
`Ctrl+Shift+F2`). Ввод клавиш обрабатывается только локальным `keydown` в
открытом floating окне (`src-soundpanel/SoundPanelApp.vue:169-186`). Это
развязывает руки: в runtime-режиме нет набора текста, поэтому буквы A–Z и
цифры 0–9 можно ловить напрямую без модификаторов.

Модель данных уже подходит без миграции: `SoundBinding { key: char (A–Z),
description, filename, original_path }`, ограничение A–Z валидируется в
`bindings.rs:42-46`. Хранение — `soundpanel_bindings.json` через команды
`sp_get_bindings` / `sp_add_binding` / `sp_remove_binding` / `sp_*_set`. Новый
UI будет читать и писать те же команды, поэтому **миграция данных не
требуется** — биндинги сохраняются как есть.

## Цель

Превратить саундпанель в **раскладку клавиатуры** (буквы + цифры), которая в
зависимости от режима либо воспроизводит звук по нажатию (runtime), либо
открывает диалог назначения файла и описания (config). Управление фокусом,
слоями и режимами — с клавиатуры, без глобальных хоткеев.

## Продуктовый контракт

1. Внутри окна саундпанели рендерится сетка-раскладка: буквы A–Z и цифры 0–9.
   Старый вид-таблица биндингов (`SoundPanelTab.vue`) убирается.
2. Два режима, переключаемых кнопкой в окне и хоткеем `Ctrl+B`:
   - **runtime** — нажатие клавиши (физической или клик по ячейке сетки)
     воспроизводит привязанный звук активного слоя;
   - **config** — нажатие клавиши / клик открывает диалог выбора файла и
     описания. Окно по нажатию **не закрывается** (persistent-режим уже
     реализован).
3. Слои (бывшие `SoundSet`) переключаются клавишами `PageUp` / `PageDown`,
   прямым выбором `F1–F12` и центральным виджетом слоёв в окне. Виджет —
   **селектбокс** (dropdown), чтобы выбирать слой раскрытием списка, а не только
   перебором.
4. Стрелки `← → ↑ ↓` перемещают фокус по сетке раскладки (2D-навигация с
   переносом на соседний ряд).
5. При открытии окна фокус снимается с активного элемента
   (`document.activeElement.blur()`), чтобы `:focus`-подсветка от клика/клавиши
   не висела и не вызывала случайных повторных срабатываний.
6. В config-режиме рядом с селектбоксом слоёв появляются кнопки управления:
   **«+»** (добавить слой → `sp_add_set`) и **удаление через confirm** (диалог
   подтверждения → `sp_remove_set`). Confirm-диалог уже существует
   (`useSoundPanel.ts:124`, `confirm("Удалить набор …?")`) и переиспользуется.
   В runtime-режиме этих кнопок нет.
7. Миграция данных не выполняется. Биндинги читаются и пишутся через
   существующие `sp_*` команды без изменения формата `soundpanel_bindings.json`.
8. Floating/drag и возврат фокуса сохраняются. Persistent-поведение получает
   собственную кнопку-гвоздик в заголовке и единый persisted source of truth.
9. Из главного UI убирается саундпанель как встроенная панель: удаляется пункт
   `soundpanel` из `Sidebar.vue` (`sidebarGroups`, строка 94 —
   `{ id: 'soundpanel', label: 'Звуковая панель', icon: Music }`) и значение
   `'soundpanel'` из типа `Panel` + блок
   `<SoundPanelTab v-show="currentPanel === 'soundpanel'" />` (`App.vue:28,381`).
   Floating-окно саундпанели (`toggleSoundPanel`, кнопка в titlebar) остаётся —
   именно оно становится единственным входом в саундпанель.

## Принятые решения

- **Старый config-вид (таблица биндингов) удаляется полностью.** Назначение
  звуков живёт только в config-режиме сетки раскладки.
- **Нет глобальных хоткеев.** Ввод обрабатывается только в открытом окне.
- **F1–F12 — локальная навигация слоёв, а не глобальные хоткеи.** Пока
  SoundPanel активен, они имеют приоритет над глобальным Intercept приложения.
- **Ctrl+B свободен** (проверено grep по фронту и Rust globalShortcut).
- **Миграция отклонена по умолчанию.** Сохранение биндингов тривиально, т.к.
  модель данных уже соответствует; если на этапе реализации всплывёт
  несовместимость — отказываемся от переноса старых данных, а не усложняем.

## Этапы

Этапы намеренно разбиты так, чтобы каждый был отдельной задачей для
DeepSeek/Qwen через `docs/development/ai-workflow.md`, проверялся независимо и
не ломал существующий конфиг до момента перехода.

### P1 — Фокус-менеджмент и слои (низкий риск, без смены парадигмы)

1. При открытии floating-окна саундпанели снимать фокус с активного элемента
   (`document.activeElement.blur()`), в т.ч. после действий пользователя, где
   это уместно (клик по кнопке/клавише).
2. `PageUp` / `PageDown` → переключение слоёв (переиспользовать
   `switchSet`/`sp_set_active_set`). Слои = существующие `SoundSet`.
   `F1–F12` выбирают слой по индексу без циклического перехода.
3. Виджет слоёв в окне (`src-soundpanel/SoundPanelApp.vue`): показывает активный
   слой и позволяет переключать. **Реализуется сразу как селектбокс**
   (dropdown) — это финальный вид, не временный; на P2 рядом с ним появятся
   кнопки управления.
4. Курсорные стрелки `← → ↑ ↓` — навигация фокуса по текущему списку/сетке
   биндингов (временная реализация до P3).

**Проверка:** окно открывается без висящего фокуса; PageUp/PageDown и F1–F12
меняют слой и это отражается в селектбоксе; отсутствующий F-индекс игнорируется;
селектбокс переключает слой; стрелки перемещают фокус.

### P2 — Режимы runtime/config, управление слоями, удаление из главного UI (средний риск)

1. Ввести состояние режима `mode: 'runtime' | 'config'` в floating-окне.
2. Кнопка toggle режима в удобном месте окна + локальный хоткей `Ctrl+B`
   (`document.addEventListener('keydown')` с проверкой `ctrlKey && key === 'b'`,
   без `preventDefault` на чужие биндинги).
3. В config-режиме нажатие клавиши / клик открывает диалог выбора файла и
   описания (переиспользовать `browseFile`/`addBinding`/`sp_add_binding`). Окно
   не закрывается (persistent уже работает).
4. В config-режиме рядом с селектбоксом слоёв появляются кнопки **«+»**
   (`sp_add_set` через `addSet`/`confirmAddSet`) и **удаление через confirm**
   (`removeSet` → `confirm(...)` из `useSoundPanel.ts:124` → `sp_remove_set`).
   В runtime-режиме этих кнопок нет.
5. **Удалить саундпанель из главного UI:** убрать пункт
   `{ id: 'soundpanel', ... }` из `sidebarGroups` в `Sidebar.vue:94`, значение
   `'soundpanel'` из типа `Panel` (`App.vue:28`) и блок
   `<SoundPanelTab v-show="currentPanel === 'soundpanel'" />` (`App.vue:381`).
   Floating-окно и кнопка `toggleSoundPanel` в titlebar остаются.
6. В runtime-режиме — текущее поведение воспроизведения.

**Проверка:** Ctrl+B переключает режим; в config нажатие открывает диалог и не
закрывает окно; «+» создаёт слой, удаление требует confirm; в runtime нажатие
играет звук; в sidebar нет пункта саундпанели и встроенная панель не рендерится.

### P3 — Сетка раскладки клавиатуры (высокий риск, основная переработка UI)

1. Новый компонент сетки: клавиши A–Z и 0–9, отрисованы в форме QWERTY-рядов.
   Каждая ячейка показывает состояние «привязан/пуст» и подсвечивается при
   нажатии.
2. Сетка общая для runtime и config; меняется только обработчик нажатия.
3. Стрелки `← → ↑ ↓` — 2D-навигация по сетке с переносом на соседний ряд.
4. Старый `SoundPanelTab.vue` удаляется после того, как его config-функции
   (выбор файла, описание, управление слоями) переносятся в config-режим сетки.

**Проверка:** раскладка корректна; клик и физическое нажатие работают в обоих
режимах; стрелки навигируют с переносом рядов; старый компонент удалён без
потерь функций.

## Что не входит

- Глобальные хоткеи для клавиш звуков (намеренно отказались).
- Изменение поведения самого окна (открытие/закрытие, floating, drag).
- Миграция данных.
- Звуковые триггеры за пределами букв и цифр. F1–F12 используются только для
  выбора слоя, стрелки — только для навигации.

## Риски

- **Дублирование логики между `SoundPanelTab` и `SoundPanelApp`.** Сейчас два
  компонента держат похожую логику. На P3 нужно вынести общую часть (выбор
  файла, слои) в `useSoundPanel`, чтобы не плодить третью копию.
- **2D-навигация стрелками по QWERTY-рядам** требует аккуратного маппинга
  «стрелка вправо с конца ряда → начало следующего»; ряды разной длины.
  Обычная ошибка — зацикливание или пропуск клавиш.
- **Удаление `SoundPanelTab.vue` (822 строки)** на P3 — большой diff,高い
  риск задеть регистрации/импорты. Требует проверки сборки фронта и ручного
  прохода по всем функциям config.
- **Ctrl+B** — локальный listener; убедиться, что не конфликтует с
  браузерными/Tauri дефолтами в окне, и не срабатывает в текстовых полях
  config-диалога.

## Доработки UI (2026-08-08 — 2026-08-10)

Все перечисленные функциональные доработки реализованы. Нативный popup WebView2
заменён собственным DOM-меню и остаётся на повторной визуальной проверке.

1. **Ширина окна.** Floating-окно расширено, чтобы в title-bar влезали все
   кнопки (в config-режиме: mode-toggle, селектор слоя с «+»/«×», закрытие).
2. **Кнопка режима.** Mode-toggle находится справа и использует
   иконку-шестерёнку.
3. **Config-режим и blur.** Config-mode подавляет blur-скрытие, включая время
   работы native file picker.
4. **Селектор слоя по центру.** Виджет выбора слоя выровнен по центру title-bar.
5. **Порядок кнопок слоёв.** «+» и «×» находятся после кнопки «вправо»
   (▶): `◀ [select] ▶ + ×` вместо текущего `◀ + × [select] ▶`.
6. **Стили диалога и селекта.** Диалог следует палитре панели; выбор слоя
   реализован собственной кнопкой и полупрозрачным DOM-меню, поэтому не зависит
   от белого системного popup WebView2.
7. **Границы кнопок.** Клавиши сетки имеют видимую границу.
8. **Ввод описания.** `onKeydown` не перехватывает буквы и цифры при открытом
   config-диалоге.
