# ROADMAP-088 — One-shot OCR выделенной области

## Цель

Добавить в TTSBard базовый локальный OCR, чтобы пользователь мог получить текст
с экрана и озвучить его без запуска и настройки второй программы.

MVP выполняет только один сценарий:

```text
Ctrl+Shift+P
    → сохранить кадр виртуального рабочего стола
    → выделить прямоугольную область на замороженном кадре
    → распознать локальной ONNX-моделью
    → передать текст в существующие «Входящие»
```

Обоснование и выбор model family зафиксированы в
[исследовании встроенного OCR](../../research/16-built-in-screen-ocr-feasibility.md).

## Пользовательский контракт MVP

1. В sidebar появляется новый раздел `OCR`.
2. В панели есть persisted-переключатель `Включить OCR`.
3. Под переключателем постоянно видна подпись:
   `Если включено, OCR будет запущен автоматически при следующем запуске приложения.`
4. Включение без перезапуска инициализирует OCR runtime и регистрирует его
   глобальную горячую клавишу. Выключение останавливает runtime и освобождает
   горячую клавишу.
5. При старте приложения сохранённое значение применяется автоматически: если
   OCR включён, runtime запускается и горячая клавиша регистрируется.
6. Default hotkey — `Ctrl+Shift+P`. Она настраивается в существующем разделе
   `Горячие клавиши` и участвует в общей проверке конфликтов сочетаний.
7. Нажатие hotkey снимает виртуальный рабочий стол до показа временного
   selection overlay. Пользователь выделяет область на замороженном кадре;
   после выбора она вырезается из того же кадра для одного распознавания,
   overlay скрывается.
8. `Escape` отменяет выбор без OCR-запроса и без создания входящего элемента.
9. Распознанный непустой текст поступает в существующий incoming flow с
   источником `ocr` и принудительной delivery policy `audio_only`.
10. Пустой результат и ошибка распознавания не создают speech job; пользователь
    получает понятное ненавязчивое уведомление.

Постоянного OCR-окна нет. Главная панель нужна только для включения, выбора
модели, показа статуса и доступа к каталогу model packs.

## Model packs

Корневой каталог:

```text
%APPDATA%\ttsbard\models\ocr\
```

Каждая непосредственная подпапка является самостоятельным model pack:

```text
models\ocr\
└─ eslav-ppocrv5-mobile\
   ├─ manifest.json
   ├─ det.onnx
   ├─ rec.onnx
   └─ dict.txt
```

`manifest.json` содержит стабильный `id`, отображаемое имя, языки, family и
имена файлов. Scanner не уходит глубже одной model-pack директории, не следует
по symlink/junction и показывает в выборе только полностью валидные packs.
Повреждённый pack не должен ломать загрузку остальных моделей.

Панель OCR выводит список найденных валидных моделей и сохраняет выбранный
`model_id`, а не абсолютный путь. Рядом показывается каталог models и действие
его открытия. Повторное сканирование доступно без перезапуска приложения.

Первый поддержанный и проверенный benchmark-ом pack:

- `PP-OCRv5_mobile_det`;
- `eslav_PP-OCRv5_mobile_rec`;
- соответствующий словарь;
- языки RU/EN с дополнительной поддержкой BE/UK.

Пользователь самостоятельно скачивает model pack и размещает его в указанном
каталоге AppData. Модели не включаются в установщик или ресурсы приложения;
автоматическое скачивание и установка моделей приложением не входят в MVP.
После размещения файлов пользователь обновляет список моделей в панели OCR
и включает функцию. Отсутствие установленной модели — штатное пустое состояние,
а не дефект упаковки приложения.

Если выбранная модель исчезла или стала невалидной, обновление списка сохраняет
работающий runtime, удерживающий её в памяти. Если такого runtime нет, функция
отключается с сохранением настройки. Единственный доступный pack может быть
выбран автоматически, но не запускается автоматически после такого отключения.
Правила выбора, повторного сканирования и ошибок определяет
[ROADMAP-090](./090-ocr-ruaccent-model-panel-behavior.md).

## Настройки и runtime truth

Минимальная persisted-секция OCR содержит:

```text
enabled: bool
model_id: string | null
hotkey: Ctrl+Shift+P по умолчанию
```

Hotkey хранится в общем hotkey settings contract, а не дублируется в OCR
section. `enabled` выражает desired state; UI отдельно показывает фактический
runtime status:

- `Выключен`;
- `Запускается`;
- `Готов`;
- `Выбор области`;
- `Распознавание`;
- `Ошибка`.

Сохранённая галка не является доказательством готовности. Неудачный запуск
runtime, включая ошибку загрузки модели или регистрации hotkey, снимает галку
с сохранением настройки; ошибка остаётся видимой. Повторный запуск выполняется
явным включением OCR по правилам ROADMAP-090. Ошибки отдельной операции захвата
или выделения обрабатываются отдельно от ошибки запуска runtime.

Регистрация сочетания выполняется только при включённом OCR. При смене hotkey
старое сочетание освобождается только после успешной регистрации нового либо
восстанавливается при неуспехе, чтобы настройка и runtime не расходились.

## Selection и screenshot

MVP поддерживает только интерактивное выделение прямоугольника на текущем
виртуальном рабочем столе Windows:

- selection overlay не забирает участие в OBS/WebView/Twitch delivery;
- координаты корректны при отрицательных координатах мониторов и Windows DPI;
- выбор нормализуется независимо от направления движения мыши;
- слишком маленькая или нулевая область отклоняется;
- повторное нажатие hotkey во время выбора/OCR не создаёт параллельные сессии;
- исчезновение монитора/окна и ошибка screenshot завершают операцию без stale
  результата.

В MVP не сохраняется последняя область и нет привязки к HWND. Каждый вызов
hotkey начинает новое выделение.

## OCR pipeline

Минимальный локальный pipeline:

```text
Screenshot
  → нормализация pixel format
  → PP-OCR detection
  → crop найденных строк
  → PP-OCR recognition
  → сортировка в порядке чтения
  → нормализация пробелов/переносов
  → incoming submit
```

Orientation classifier, перевод, AI-коррекция OCR, автоматический выбор языка и
рендеринг распознанного текста поверх игры не входят в MVP. Общие настройки
preprocessing/TTS применяются уже после поступления текста в существующий
speech flow.

До продуктовой реализации нужен небольшой benchmark на корпусе игровых
RU/EN-скриншотов. Он фиксирует качество распознавания, end-to-end latency на CPU
и необходимые пороги detection. Benchmark не расширяет UI scope.

## Интеграция с «Входящими»

Новая очередь не создаётся. OCR вызывает тот же application-level incoming
submit seam, который используется Input Server:

- при включённом автовоспроизведении создаётся обычная audio-only speech job;
- в ручном режиме текст становится `pending_review`;
- доступны существующие действия `Озвучить`, `Редактировать`, `Отклонить`;
- WebView и Twitch никогда не получают OCR-текст;
- activity/inbox DTO различает источники `server` и `ocr`.

Настройка автовоспроизведения в MVP остаётся общей политикой входящих, а не
дублируется для каждого producer. Её текущее владение Input Server должно быть
переименовано/перенесено на source-neutral уровень без миграционной потери
значения.

Вкладка `Входящие` показывается, если выполняется хотя бы одно условие:

- Input Server работает;
- OCR runtime включён;
- существуют pending или активные incoming items.

Выключение OCR не скрывает уже принятые элементы и не отменяет speech jobs.

## Не входит в MVP

- постоянная отслеживаемая область;
- периодический захват и сравнение кадров;
- автоматическая стабилизация и дедупликация реплик;
- несколько областей и профили игр;
- привязка области к окну или процессу;
- перевод и overlay распознанного текста;
- JP/EN, manga-ocr и автоматическое переключение моделей;
- игровые hooks и эмуляторы;
- облачные OCR-провайдеры;
- поставка моделей с приложением и встроенный загрузчик моделей;
- OCR файлов, буфера обмена и истории изображений.

## Этапы реализации

### P0 — benchmark и исполнимый model contract — выполнено

- собрать небольшой versioned корпус RU/EN игровых кадров;
- подтвердить PP-OCRv5 mobile через используемый ONNX Runtime;
- зафиксировать preprocessing/postprocessing и `manifest.json`;
- измерить CPU latency и качество до построения UI.

Результат: model contract и runtime закоммичены (`src-tauri/src/ocr/`),
benchmark на реальных игровых кадрах — в
[исследовании 18](../../research/18-ocr-ppocrv5-eslav-benchmark.md). Выбор
eSlav PP-OCRv5 mobile подтверждён; точки настройки детектора переданы в P2/P3.

### P1 — settings, scanner и runtime lifecycle — выполнено

- добавить persisted OCR settings и DTO;
- реализовать безопасный scanner `models/ocr/<model-id>`;
- добавить lifecycle/status и условную регистрацию global hotkey;
- покрыть migration, invalid pack и hotkey conflict тестами.

Результат: коммиты `0a7dd42` (settings + hotkey-контракт), `57f20cf`
(сервис lifecycle, команды, условная регистрация), `d21e018` (редактируемость
`ocr_capture` в существующем разделе хоткеев + retry при ошибке).

### P2 — selection и one-shot OCR — выполнено

- реализовать временный selection overlay и screenshot;
- выполнить detection/recognition без блокировки UI;
- корректно обрабатывать cancel, re-entry, ошибки и stale result.

### P3 — incoming integration и панель — выполнено

- добавить OCR source в общий incoming submit seam;
- отвязать видимость `Входящих` и auto-play policy от одного HTTP-сервера;
- добавить sidebar-панель OCR, модель, статус и кнопку rescanning/open folder;
- проверить audio-only invariant для WebView/Twitch.

### P4 — ручная установка моделей и release-smoke — выполнено

- проверить штатное пустое состояние на чистом профиле без моделей;
- проверить обнаружение вручную установленного eSlav model pack через обновление
  списка и запуск OCR без перезапуска приложения;
- проверить upgrade существующего профиля с пользовательскими моделями;
- пройти ручной сценарий `Ctrl+Shift+P → область → Входящие → аудио` на
  нескольких мониторах и масштабах Windows.

## Критерии завершения

- OCR можно включить, выключить и оставить включённым между запусками;
- при включённом OCR default/custom hotkey зарегистрирован, при выключенном —
  освобождён;
- пользователь выбирает область и получает ровно один результат либо понятную
  отмену/ошибку;
- модель выбирается из валидных подпапок AppData и не зависит от абсолютного
  пути в settings;
- вручную установленный поддерживаемый RU/EN pack работает полностью локально;
- результат проходит существующий automatic/review incoming flow;
- OCR-текст и его производные не доставляются в WebView или Twitch;
- нет постоянного OCR-окна, фонового screen polling и игровых hooks.

## Outcome

Реализован локальный one-shot OCR: model packs и ONNX runtime, включение и
настраиваемая горячая клавиша, выделение области на замороженном кадре,
распознавание и передача результата в общий incoming flow с audio-only policy.
Панель поддерживает выбор модели, повторное сканирование и открытие каталога;
модели устанавливаются вручную и не входят в поставку приложения.

2026-09-04 пользователь подтвердил работоспособность перечисленных сценариев
ручной приёмки, включая установку моделей, upgrade и полный путь от выделения
до аудио. Отдельно подтверждён OCR на двух экранах с монитором слева от основного
(отрицательные координаты виртуального рабочего стола). Ручная приёмка выполнена
пользователем; повторная проверка интерфейса агентом не проводилась.

Lifecycle моделей и его итоговая приёмка описаны в
[ROADMAP-090](./090-ocr-ruaccent-model-panel-behavior.md).
