# ROADMAP-102 — Чистый список и управляемая видимость автодополнения

## Контекст

CodeMirror сейчас показывает рядом с локальными подсказками служебную частоту:
`слово (12)` для слов из истории и `продолжение →7` для продолжений фраз.
Число полезно алгоритму ранжирования, но перегружает пользовательский список.

Локальное обучение и показ подсказок — независимые процессы. После успешной
отправки `InputPanel.vue` вызывает `record_history`; именно этот путь обновляет
частоты слов и фраз. Запросы `get_history_suggestions` и
`get_phrase_completion` только читают накопленную статистику для выдачи.

## Цель

Сделать autocomplete спокойнее визуально и дать пользователю общий выключатель
его подсказок, не прекращая накопление локальной истории и частот.

## Продуктовое решение

1. В popup автодополнения не показывать числовые частоты слов и продолжений
   фраз. Поля `count` остаются во внутренних контрактах и продолжают определять
   порядок результатов на backend: чаще использованные варианты идут первыми.
2. В `Настройки → Редактор` добавить persisted-флажок
   «Показывать подсказки автодополнения», включённый по умолчанию для обратной
   совместимости.
3. Когда флажок выключен, popup не открывается и источники подсказок не
   запрашиваются. Это относится ко всему CodeMirror autocomplete: словам из
   истории, продолжениям фраз, AI-продолжению и preset-подстановкам `\\...` /
   `%...`.
4. Запись успешно отправленного текста через `record_history` остаётся активной
   независимо от флажка. После повторного включения предложения используют всю
   статистику, накопленную за время скрытия.
5. Существующая настройка `editor.ai_completion` остаётся отдельным разрешением
   AI-слоя. AI-запрос выполняется только когда включены и общий autocomplete, и
   AI completion.

Это не только CSS-скрытие popup. При скрытом UI вычислять локальные варианты и
тем более отправлять AI-запросы бессмысленно; для продолжения обучения они не
нужны. Настройка управляет выдачей, а не сбором статистики.

## Scope реализации

### P1 — Убрать счётчики из представления

- В `src/components/editor/TtsEditor.vue` удалить только `detail`, содержащие
  `w.count` и `p.count`.
- Не менять `Suggestion.count`, `PhraseSuggestion.count`, backend-модели,
  сортировку, лимиты и дедупликацию.
- Содержательные подписи `AI` и раскрытие preset-подстановок не являются
  числовыми счётчиками, но исчезают вместе со всем popup при выключенном общем
  флажке.

### P2 — Persisted-настройка

- Добавить в `EditorSettings` булево поле `autocomplete_enabled` с serde-default
  `true`, чтобы старые `settings.json` сохраняли текущее поведение.
- Провести поле через `EditorSettingsDto` и TypeScript `EditorSettingsDto`.
- Добавить setter в `SettingsManager`, Tauri-команду с `persist_blocking` и
  `settings-changed`, затем зарегистрировать её в invoke handler.
- Добавить флажок и пояснение в `SettingsEditor.vue`, русскую и английскую
  локализацию в обоих канонических каталогах приложения.
- При ошибке сохранения UI должен вернуться к фактическому persisted-состоянию и
  показать существующее глобальное сообщение об ошибке.

### P3 — Runtime-поведение редактора

- Реактивно применять настройку в уже открытом редакторе без перезапуска и без
  фиктивного ввода.
- При выключении немедленно закрывать уже открытый popup и не допускать открытия
  нового, включая explicit completion.
- Не запускать `get_history_suggestions`, `get_phrase_completion` и
  `get_ai_completion`, пока autocomplete выключен; поздний результат запроса,
  начатого до выключения, не должен снова показать popup.
- Не менять `record_history`, историю фраз, очистку истории, порядок кандидатов,
  клавиши отправки и spellcheck.

## Риски и граничные случаи

- Простая проверка настройки только в начале async source недостаточна: флажок
  может измениться, пока backend или AI отвечает. Нужна защита от stale result.
- Если расширение autocomplete полностью удаляется и добавляется обратно,
  необходимо сохранить корректный приоритет Enter/Escape и editor hotkeys.
- Общий флажок намеренно сильнее `ai_completion`: включённый AI-слой не должен
  обходить скрытие autocomplete.
- Старые конфиги без нового поля должны десериализоваться как `true`; явное
  `false` должно переживать round-trip и перезапуск.

## Критерии готовности

- [x] В подсказках слов и продолжений фраз нет чисел в скобках или после
      стрелки; порядок по `count desc` не изменился.
- [x] Новый флажок находится в настройках редактора, сохраняется и по умолчанию
      включён для существующих пользователей.
- [x] Выключение сразу закрывает popup; ввод и explicit completion не вызывают
      ни локальные, ни phrase-, ни AI-источники.
- [x] Отправленный при выключенных подсказках текст по-прежнему записывается в
      историю и влияет на порядок после повторного включения.
- [x] Переключение работает без перезапуска, в обеих темах и при узкой ширине.
- [x] Ошибка сохранения не оставляет checkbox в ложном состоянии.
- [x] Сохранены контракты Enter/Escape/Tab и spellcheck context menu.

## Проверка

- Unit-тесты сериализации/default/round-trip `EditorSettings` и DTO mapping.
- Frontend-тесты gate для включённого, выключенного и stale async состояний;
  отдельно проверить отсутствие invoke каждого источника при `false`.
- Тест/контракт отображения вариантов без числового `detail` при сохранённом
  порядке backend-результата.
- Ручной сценарий: выключить при открытом popup, отправить повторяющуюся фразу,
  включить обратно и убедиться, что popup учитывает новую частоту.
- `npm test`, затем `npm run build`.
- `scripts/cargo.ps1 test` для затронутых Rust-модулей и
  `scripts/cargo.ps1 check`.

## Outcome

Числовые частоты убраны из вариантов слов и фраз без изменения backend-
ранжирования. В настройках редактора появился включённый по умолчанию общий
флажок автодополнения, который сохраняется, применяется без перезапуска и
отключает history-, phrase-, AI- и preset-источники, не останавливая обучение
через `record_history`.

Асинхронные источники повторно проверяют флажок после завершения запросов,
включая ошибочное завершение history-запроса, поэтому выключение не пропускает
следующий слой и поздний результат не открывает popup. Сохранение checkbox
сериализовано: на время команды он недоступен, а ошибка возвращает последнее
подтверждённое persisted-значение.

Ручной пользовательский сценарий проверен перед финальным ревью. Автоматически
прошли 1124 frontend-теста, production build, settings parity, проверка
документации, 1899 Rust-тестов и Rust check.
