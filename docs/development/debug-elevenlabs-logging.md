# HTTP-диагностика ElevenLabs в debug-сборке

Для диагностики запросов и неожиданных ответов ElevenLabs можно явно включить
подробный HTTP-лог:

```powershell
$env:TTSBARD_LOG_ELEVENLABS_HTTP = "1"
./scripts/build.ps1 -Mode debug
./src-tauri/target/debug/ttsbard.exe
```

Переменную нужно задать в том же PowerShell, из которого запускается приложение.
Перед запуском полностью закройте уже работающее приложение из трея: действует
ограничение на один экземпляр.

Записи имеют tracing target `elevenlabs_http`. В них входят метод, безопасный
URL, операция, категория и страница списка голосов, использование прокси,
таймаут, статус, время ответа, content type/length и ограниченное текстовое тело
ответа. Успешное бинарное аудио не записывается.

API-ключ всегда заменяется на `<redacted>`, учётные данные прокси удаляются,
значение `next_page_token` скрывается, а для текста синтеза сохраняется только
длина. Тела ответов могут содержать названия пользовательских голосов, сведения
об аккаунте и другие данные ElevenLabs. Перед передачей лога третьим лицам его
необходимо проверить и при необходимости очистить.

Режим включается только при точном значении `1` и только в debug-сборке. В
release-сборке диагностические функции являются compile-time no-op. В debug
записи выводятся в консоль; запись в `%APPDATA%/ttsbard/logs/ttsbard.log`
дополнительно требует включённого логирования в настройках приложения.

После диагностики удалите переменную из текущей сессии:

```powershell
Remove-Item Env:TTSBARD_LOG_ELEVENLABS_HTTP
```
