# Twitch Chat

Отправка TTS сообщений в Twitch чат для дублирования.

Поддерживаются два режима подключения:

## 1. Режим Twitch API

Использует официальный Twitch Helix API (`POST /helix/chat/messages`).
Сообщения доставляются от имени авторизованного аккаунта бота в чат стримера. Боту **не требуются** права модератора канала.

**Настройка:**
1. Создайте приложение в [Twitch Developer Console](https://dev.twitch.tv/console/apps):
   категория «Chat Bot», тип клиента «Confidential».
2. Введите Client ID и Client Secret и нажмите «Сохранить».
3. Нажмите «Авторизоваться» у аккаунта бота. Откройте ссылку активации и
   подтвердите доступ под отдельным аккаунтом бота (`user:write:chat`, `user:bot`).
4. Нажмите «Добавить канал» и подтвердите доступ под аккаунтом его владельца
   (`channel:bot`). Ссылку можно скопировать владельцу или открыть в другом
   браузере/на другом устройстве. Браузер не открывается автоматически.
   Держите TTSBard открытым до завершения, ожидание — до 5 минут.
5. Выберите один канал-получатель. Первый добавленный канал выбирается автоматически.
6. Нажмите «Подключиться» для активации отправки.

Оба аккаунта авторизуются через Device Code Flow: локальный callback при входе
не используется. Если консоль требует OAuth Redirect URL при регистрации,
можно оставить `http://localhost`; при входе по коду
перенаправления на него не происходит.

Кнопка сброса бота удаляет сохранённый вход бота, отменяет ожидание
авторизации и останавливает API-подключение. Client ID и Client Secret
сохраняются. Сброс действует только локально; отозвать разрешение на стороне
Twitch можно в настройках Twitch → Подключения.

Смена канала-получателя при активном подключении автоматически обновляет и
перезапускает подключение API на нового получателя.

Кнопка «Удалить доступ» у строки канала забывает грант **локально**: сохранённые
токены канала стираются на этом компьютере, запрос на отзыв доступа (revoke) на
Twitch не отправляется. Забытый канал можно добавить заново. Если удалён выбранный
канал, получатель сбрасывается и API-подключение останавливается.

## 2. Режим IRC (классический)

Прямое подключение бота через IRC-сокет.

**Настройка:**
1. Создайте токен для бота на [twitchtokengenerator.com](https://twitchtokengenerator.com)
2. Скопируйте OAuth токен со страницы (только сам токен, без префикса `oauth:`)
3. Введите логин бота, имя целевого канала и токен
4. Нажмите «Подключиться»

**Поля настроек IRC:**
- **Username / Логин** — логин аккаунта OAuth-токена, 1–25 латинских букв,
  цифр или `_` (без `@` и пробелов)
- **Token** — только токен (без `oauth:`)
- **Channel / Канал** — имя канала без URL и `#`, например `twitchdev`;
  1–25 латинских букв, цифр или `_`

Если первое подключение IRC не подтверждено за 30 секунд, попытка останавливается
со статусом ошибки. Проверьте имя канала и соединение, затем повторите
подключение вручную.

После временного обрыва сети или команды Twitch `RECONNECT` приложение само
переподключается. В заголовке на это время отображается состояние подключения;
ручное «Отключиться» останавливает фоновые попытки. Реплика, при отправке
которой оборвалось соединение, не посылается повторно автоматически: её стоит
отправить снова только если это уместно.

Перед отправкой выберите [маршрут редактора](../user/editor.md#маршрут-фразы), включающий Twitch. Входящие HTTP/OCR автоматически в чат не отправляются.

Ошибки формата показываются рядом с полем до исправления. Если логин не
соответствует аккаунту OAuth-токена, подключение прекращается сразу с отдельным
сообщением. Причина ошибки подключения остаётся в панели до новой попытки либо
отключения. Кнопки подключения и переподключения сохраняют изменённые реквизиты
перед подключением; тост операции сообщает об этом отдельной частью сообщения.

Лог приложения содержит коды причин отказа и сведения о повторной попытке.
Сырой IRC-трафик сторонней библиотеки не выводится даже при TRACE, поскольку
команды PASS и PRIVMSG содержат токен и пользовательский текст.

## Обновление панели — второй этап

Согласовано 2026-10-10: управление подключением и две общие галки остаются сверху; ниже разделитель, выбор IRC/API, реквизиты, разделитель и «Сохранить». В API под сохранением размещаются панели бота и каналов друг под другом. Отдельное поле Redirect URL убрано из формы; оба аккаунта используют вход по коду. Под карточками доступен отдельный сброс авторизаций с сохранением реквизитов. Client ID скрыт по умолчанию и доступен для просмотра. Сохранённый Client Secret показан статусом: значок карандаша рядом со статусом «Сохранён» открывает пустой ввод, крестик отменяет замену, «Сохранить» заменяет секрет только после успешной записи. Глаз показывает только новый ввод. Смена режима останавливает подключение до ручного запуска, даже если реквизиты нового режима ещё не заполнены.

Расширение до нескольких каналов реализовано: панель хранит список авторизованных
каналов и один выбранный канал-получатель. Добавление канала идёт через Device Code
Flow с явным копированием/открытием ссылки, удаление доступа выполняется только
локально. Отзыв доступа на стороне Twitch пока не выполняется.
