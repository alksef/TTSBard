# Входящий сервер текста

Входящий сервер принимает текст от других программ на этом же компьютере и
передаёт его в обычный цикл озвучивания TTSBard. Внешнее приложение отвечает
только за получение или подготовку текста; синтез и воспроизведение выполняет
TTSBard.

Сервер использует активный TTS-провайдер и голос, настройки препроцессора,
AI-коррекции и RUAccent, аудиоэффекты, динамики и виртуальный микрофон. Входящие
реплики предназначены только для аудио: они не отправляются в WebView и Twitch.

## Запуск и настройка

1. Откройте **Интеграция → Входящий сервер**.
2. При необходимости измените порт. Допустимый диапазон — `1024–65535`, порт
   по умолчанию — `10101`.
3. Нажмите **Сохранить**, затем **Запустить**.
4. Убедитесь, что состояние изменилось на **Работает**.

Порт нельзя изменить у уже запущенного сервера: сначала остановите его,
сохраните новое значение и запустите снова. Настройка **«Запускать при старте
приложения»** автоматически запускает listener при следующем запуске TTSBard.

Сервер всегда слушает только `127.0.0.1`. Подключиться к нему с другого
компьютера нельзя; настройки LAN-доступа, CORS и UPnP к этой интеграции не
применяются.

## Обработка принятых реплик

Автовоспроизведение, ручной разбор и горячие клавиши описаны в общей
инструкции [«Входящие»](./incoming.md). Она относится и к HTTP-серверу, и к OCR.

## Подключение приложения

Панель показывает готовый endpoint, который можно скопировать кнопкой справа:

```text
http://127.0.0.1:10101/v1/speech
```

Клиент должен отправить `POST` с заголовком `Content-Type: application/json` и
полем `text`:

```json
{
  "text": "Проверка входящего сервера"
}
```

Пример проверки из PowerShell:

```powershell
curl.exe http://127.0.0.1:10101/health
curl.exe -X POST http://127.0.0.1:10101/v1/speech `
  -H "Content-Type: application/json" `
  -d '{"text":"Проверка входящего сервера"}'
```

Исправный сервер возвращает `{"status":"ok"}` для `/health`. В автоматическом
режиме принятая реплика получает ответ `202 Accepted` с `job_id` и состоянием
`queued`; в ручном режиме — с `incoming_id` и состоянием `pending_review`.

Максимальная длина текста — 20 000 Unicode-символов, максимальный размер тела
HTTP-запроса — 64 КиБ.

## Проверка без внешней программы

В блоке **«Тест»** панели сервера введите реплику и нажмите **«Отправить»**.
При включённом автовоспроизведении она попадёт в очередь речи; при выключенном —
во вкладку редактора **«Входящие»**. Так можно отдельно проверить TTSBard до
настройки внешнего клиента.

## Веб-форма ввода (Overlay)

Пока входящий сервер запущен, на том же порту доступна простая веб-форма для
отправки реплик из обычного браузера:

```text
http://127.0.0.1:10101/overlay
```

Порт в адресе соответствует настроенному порту сервера (по умолчанию `10101`).
Форма минималистична: только многострочное поле и область статуса, без
заголовков и кнопок. `Enter` отправляет реплику, `Shift+Enter` вставляет
перенос строки, пустая строка не отправляется. После
успешной отправки поле очищается и вновь получает фокус; результат
(`queued` или `pending_review`) отображается в области статуса.

Форму можно открыть в любом браузере на том же компьютере, где запущен
TTSBard, — Steam Overlay лишь один из возможных клиентов. Форма отправляет текст на тот же
`POST /v1/speech` и не требует CORS или внешних ресурсов.

## Типовые ошибки

| HTTP-код | Причина и действие |
|---|---|
| `400` | Некорректный JSON. Проверьте тело запроса и обязательное поле `text`. |
| `413` | Тело запроса превышает 64 КиБ. Уменьшите текст. |
| `415` | Не передан `Content-Type: application/json`. |
| `422` | Текст пустой или длиннее 20 000 символов. |
| `429` | Переполнена очередь речи или список ожидающих входящих. Повторите позже. |
| `503` | Активный TTS-провайдер или аудиовыход не готов. Проверьте настройки TTS и аудио. |

Если сервер не запускается, чаще всего выбранный порт уже занят другой
программой. Остановите использующий его процесс либо выберите другой порт,
сохраните настройку и повторите запуск.

## Пример: LunaTranslator

Для LunaTranslator в репозитории есть готовый пример selfbuild-скрипта. Он
передаёт распознанный или переведённый игровой текст во входящий сервер, не
возвращая аудио в плеер LunaTranslator, поэтому двойного воспроизведения нет.

Установка скрипта и настройка LunaTranslator описаны в
[отдельном руководстве](../integrations/lunatranslator/README.md).
